## Question 1: what do a room's tables become when furniture gets compartments?
Today a room's `contains = ["T"]` rolls T once per object. With compartments, each one rolls
its own loot, and `contains` is no longer allowed on those items. If every compartment rolls
T, a five-shelf unit gets five times today's loot. Measured: 14 of the 60 (item, table)
pairings in rooms would not fit even one compartment. For example, grocery_produce is 617 L
against a 140 L shelf, farm_barn_stock 667 L, and kids_room_stuff on a 15 L desk drawer is 30 L.
- A. Every compartment rolls the room's table, and every shared table gets a per-compartment
  variant with smaller rolls, so the total per object stays about the same. This adds about
  30 tables.
- B. The table is rolled once for the object and the generator spreads it over the
  compartments by fit. The fit check stays per object (sum of capacities), and `contains`
  stays legal.
- C. Each compartment names its own table (a drawer table, a shelf table), written by hand
  per item and room. That is more content, and the most faithful.
Builder's recommendation: B for now (loot density unchanged, no table explosion; D-027's
per-compartment search still works, because each compartment gets its share), with C later
where a room wants distinct drawers.

## Question 2: the room fit rule rejects the brief's own bedroom
Literal rule: tiles = ceil(length / 1 m) x ceil(width / 1 m) for blocking or fixed objects;
the minimum counts must fit 0.6 x the minimum size_m2. A 9 m2 bedroom then has 5.4 tiles, but
bed_frame (2030 x 1520) alone is 3 x 2 = 6 tiles, and the mattress lying on it is another 6.
So "a bedroom of 9 m2 holds a bed, a dresser and a nightstand" cannot pass whatever the
counts. Other overcounts: dims are longest-first, so tall things count their height as length
(a 1800 mm bookshelf 300 mm deep counts as 2 tiles, the pantry as 3). The garage's pickup truck
counts 18 tiles, so its maximum is 87 against 36.
- A. Keep the rule and fix rooms by raising sizes. Bedrooms become 20 m2 or more, which is
  not realistic.
- B. Count the footprint, not the length: round to the nearest tile (at least 1), use the two
  horizontal dimensions (tall items give their width x depth), and give objects that sit on
  another one (a mattress on a bed frame) no tiles of their own, via a property or a known
  pairing.
- C. Measure area instead of tiles: sum of length x width in m2 against 0.6 x size_m2.
Builder's recommendation: C (simple, honest to floor space; a 9 m2 bedroom with a 3.1 m2 bed,
a 0.9 m2 dresser and a 0.2 m2 nightstand passes), plus the mattress-on-frame exemption.

## Architect answers (2026-09-30)

**Question 1: B.** Roll the room's table once per object and spread the result over the
compartments by fit. The fit check stays per object (sum of capacities) and `contains` stays
legal on multi-compartment items. Loot density is unchanged and D-027 still holds, because
each compartment is searched for its own share. This is an interim content rule, not the end
state: under D-030, PEO-057 gives each compartment a purpose rolled from its seed that picks
its main table, and the room's table becomes the context those purposes draw from. Do not
write per-compartment table variants (option A) now.

**Question 2: C, measured on the footprint.** Sum each object's floor area in m2 against
ROOM_FILL_MAX x size_m2, at the minimum counts of always-placed objects and at every
maximum. Floor area uses the two horizontal dimensions: for an upright item (a bookshelf,
a pantry, a wardrobe) that is width x depth, not its height. Where dims_mm cannot say which
side is up, add an `upright = true` property rather than guessing from the ratio. An object
that rests on another (a mattress on a bed frame) covers no floor of its own; mark it with
a `rests_on = "<item>"` property and have lint skip it when that item is in the same room.
Blocks-none and wall-mounted items cover none, as in the diff above. Vehicles in garages
count like any object; if the garage still fails, raise its size to fit a pickup, since
real garages are sized for one.

Neither answer changes a user decision (D-027, D-030). The Builder continues with the units
in the brief, the rule adjusted as above.
