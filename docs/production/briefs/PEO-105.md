# PEO-105 · verify's license check splits SPDX expressions case-sensitively, so 'MIT OR GPL-2.0' is wrongly refused

## Goal

tools/validate_docs.py license_ok reads SPDX operators in any case (OR/AND as well as or/and), so 'MIT OR GPL-2.0' and 'Apache-2.0 AND MIT' pass while GPL-only expressions are still refused, and --self-test pins it.

## Context

- docs/domains/process.md (licensing row; ADR-0015)
- docs/LICENSING.md: 'Allowed dependency licenses' and the 'License (SPDX)' table
- tools/validate_docs.py: license_ok (lines 94-102), license_self_test (lines 153-163), allowed_licenses (lines 70-77)
- Repro (2026-10-06, origin/main): license_ok returns False for 'MIT OR GPL-2.0', 'Apache-2.0 AND MIT' and 'MIT OR GPL-2.0-or-later', True for 'MIT or GPL-2.0'. Cause: re.split(r'\band\b') and re.split(r'\bor\b|/') are case-sensitive, so uppercase operators stay inside one option string that matches no allowed id. Fails closed: false refusals only.
- Side effect of the \b form: hyphens are word boundaries, so 'GPL-2.0-or-later' is cut into 'gpl-2.0-' and '-later'. Harmless today (fragments match nothing) but wrong; match operators only between whitespace.

## Units

- tools: in license_ok, split '+' parts on r'\s\+\s|\s+and\s+' and options on r'\s+or\s+|/', both with flags=re.IGNORECASE; keep the lowercase compare and the parenthesis strip. Update the docstring to say operators are case-insensitive SPDX OR/AND.
- test: extend license_self_test with direct license_ok cases against allowed_licenses(licensing): must pass 'MIT OR GPL-2.0', 'Apache-2.0 AND MIT', 'mit or Zlib', 'BSD-3-Clause / GPL-2.0'; must refuse 'GPL-2.0 AND MIT', 'GPL-2.0-or-later', 'GPL-2.0 OR LGPL-2.1'. Each failure appends a 'license self-test: ...' problem naming the expression.

## Acceptance

- python3 tools/validate_docs.py --self-test prints 'license self-test ok' and exits 0
- Temporarily reverting the regex to the case-sensitive form makes --self-test fail on 'MIT OR GPL-2.0' (check once, do not commit the revert)
- python3 tools/validate_docs.py passes on the repo with no new errors (existing LICENSING.md rows unchanged)
- python3 tools/verify.py passes
