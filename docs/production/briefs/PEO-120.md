# PEO-120 · Look key: a movable cursor over the seen field (D-049)

## Goal

A Look key enters a look mode with a cursor on the player; the movement keys then move the cursor over the cells the player can see now (PEO-119's SightField::seen), never onto an unseen cell, without spending turns or touching the world; Look again or Escape ends it. Core owns the cursor and a per-cell look report that PEO-121 fills with what shows at each distance; the frontend only routes keys, draws a cell outline and leaves an empty text hook for Ryan's words (D-042). Whether the cursor can leave the screen is D-052; the core is built for either answer.

## Units

- core: src/core/include/peo/core/look.hpp + src/core/src/look.cpp (add to the core library sources), namespace peo::core, one concept: looking at a seen cell. Each with a doc comment saying why:
    - `class LookCursor` with `void begin(Vec2i player) noexcept;` (active, cursor on the player); `void end() noexcept;`; `[[nodiscard]] bool active() const noexcept;`; `[[nodiscard]] Vec2i cell() const noexcept;` (the cursor in stage cells, never screen cells, D-050); `bool step(Vec2i dir, int cells, const SightField& sight, CellRect bounds) noexcept;` moves up to `cells` cells along `dir` (one of the eight unit steps, asserted; cells >= 1, asserted) one cell at a time and stops before the first cell that is not `sight.seen` or lies outside `bounds`; returns whether it moved. An inactive cursor never moves (returns false). No allocation, no World access, no RNG.
    - `bounds` is the D-052 seam: the caller passes the on-screen cells (answer A) or sight.window() (answer B); the cursor itself knows nothing about screens.
    - `struct LookReport { Vec2i cell; std::int32_t distance_sq; bool player; bool opaque; bool exit; std::uint32_t dead; };` what is at a seen cell, data only: squared distance from the player in cells (PEO-121 compares it with r*r, the same disc test sight uses), the player there, the cell a wall, the exit there, how many of the Dead stand there (shared occupancy, ADR-0013).
    - `[[nodiscard]] std::optional<LookReport> look_at(const SightField& sight, const Stage& stage, std::span<const Dead> horde, Vec2i player, Vec2i cell);` nullopt for any cell `sight.seen` rejects, so nothing unseen is ever reported. Takes parts, not World, so tests build it by hand and the Dead that can see can reuse it later. PEO-121 extends LookReport with what shows at each distance (labels within 6 cells); this item adds no field for it.
    - Name every constant; `kLookJumpCells = 8` (the shifted step, a technical default) lives here too so the app has no number.
- test: tests/core/test_look.cpp (add to peo_core_tests sources), TEST_SUITE("look"), unit tier, grids of at most 32 x 32 built by hand (Stage with blocked and exit set directly), SightField computed with a small range: (1) begin puts the cursor on the player and active() is true; end makes it false and step then returns false and does not move; (2) a step onto a seen open cell moves one cell and returns true; (3) a step onto a cell behind a wall (not seen) returns false and the cursor stays; (4) a step onto the seen wall itself succeeds (walls that bound the view are seen, PEO-119); (5) step with cells = kLookJumpCells along a row stops on the last seen cell before the range edge, and on the last cell inside a `bounds` rect smaller than the window; (6) from a grid edge, a step off the grid returns false; (7) a diagonal step moves both axes; a step with a non-unit dir or cells < 1 is not tested (asserts); (8) look_at: nullopt for an unseen cell and for an off-grid cell; for seen cells it reports the player cell (player true, distance_sq 0), a wall (opaque true), the exit, and a cell with two Dead on it (dead == 2), with distance_sq equal to dx*dx + dy*dy
- app: the look mode, src/app/main.cpp. App gains `peo::core::LookCursor look;`. In SDL_EVENT_KEY_DOWN, before every other branch: while `look.active()`, the arrows and wasd call `look.step(dir, shift ? kLookJumpCells : 1, sight, bounds)` (bounds per D-052, below) and set dirty when it moved; L or Escape calls `look.end()` and sets dirty; every other key is swallowed (no turn, no stage change, no run or scent toggle), and held-key repeats move the cursor (it is not a turn, so D-032's cap does not apply). Escape no longer quits while looking; it still quits otherwise. When not looking, L calls `input.clear()` (queued taps were meant before Look), `look.begin(world.player())` and sets dirty. Nothing in look mode calls take_turn, offer, load_stage or the speculator, so the world, the turn count and the speculation are untouched. Map the keys in a small function beside action_for (`look_dir_for(SDL_Keycode) -> std::optional<Vec2i>`) so turn keys and look keys share one table of directions
- app: drawing the cursor, src/app/main.cpp draw(). While looking, outline the cursor's cell with SDL_RenderRect in a highlight colour (a named constant), after the glyphs so the outline sits over whatever is drawn there; no glyph replaces the cell's own. Placement goes through view_to_screen like the glyph lambda (the cursor is a stage cell; zoom only changes the cell size). The text hook: a function `std::string_view look_line(const peo::core::LookReport&)` that returns an empty view, with a comment that Ryan writes this text (D-042) and PEO-121 supplies the data; while looking, draw() calls look_at for the cursor cell and, only when look_line returns non-empty, draws it on the HUD's second line in place of kKeyHints. With today's empty hook the HUD is unchanged. Add no hint for the L key to kKeyHints: that is Ryan's text too
- app: the view while looking, per D-052 (wait for the answer in decisions.md). Answer A: the view stays centred on the player; bounds is the on-screen stage rect, {view_origin(player, view), view_origin(player, view) + {cols - 1, rows - 1}}, intersected with sight.window(); camera.hpp is unchanged. Answer B: bounds is sight.window(); camera.hpp gains `constexpr core::Vec2i follow_origin(core::Vec2i origin, core::Vec2i cell, View view) noexcept` returning the origin shifted the least so `cell` is in view (unchanged when it already is), with a doctest case in the existing camera test file for in view, each of the four edges and a jump of kLookJumpCells past an edge; App keeps `look_origin`, set to view_origin(player, view) on begin and advanced by follow_origin after each step; draw() uses it in place of view_origin while looking and view_origin again after end (the player is centred again, D-048). Either way, the map still draws only seen cells (PEO-119), so panning never reveals anything sight does not
- docs: docs/architecture.md 'Current code' diagram gains `look.hpp  LookCursor, look_at: the Look cursor over the seen field (PEO-120)`; docs/domains/presentation.md lists D-052 under Decisions and moves PEO-120 from Queue to Done when completing

## Manual

- `cmake --build --preset dev && ./build/dev/bin/peo`: press L; an outline sits on @. Move it with arrows and wasd, and with shift held: it covers the lit field and stops at dark cells and at walls
- Hold an arrow: the cursor runs smoothly (no 3/s cap) and the turn count does not move
- Queue a few taps of a move, press L at once: no queued step plays out after Look starts
- Press n, r and shift+s while looking: nothing happens; press L to leave, then they work again
- Press Escape while looking: Look ends, the game keeps running; Escape again quits
- Walk the cursor to the screen edge: per D-052, it stops (A) or the view scrolls and snaps back to @ when Look ends (B)
- Perf observation: on `--stage 512x512` with the default horde, hold shift+arrow while looking and report whether the cursor keeps up with key repeat (look_at walks the horde once per move)
