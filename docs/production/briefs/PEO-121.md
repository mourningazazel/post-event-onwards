# PEO-121 · What can be made out at range: labels within 20 ft (D-049)

## Goal

Looking at a seen cell within 6 cells (20 ft, D-049) tells the frontend what can be made out there, all from content data: each thing's generic label (claw_hammer shows as its generic parent hammer, D-046), a container only as its own kind (never its compartment purposes or contents, D-030), and a sign's text. Beyond 6 cells a thing is reported as present with no label (D-053 may widen this). Core owns the range rule and the label lookup; the app fills PEO-120's look_line hook with content names verbatim and adds no words of its own (D-042). Full descriptions, purposes and contents stay behind examining, which is not this item.

## Units

- core (after PEO-120): the 20 ft rule in look.hpp. `inline constexpr std::int32_t kLegibleRangeCells = 6;` with a comment: 20 ft at the D-049 tile scale. `[[nodiscard]] constexpr bool legible(std::int32_t distance_sq) noexcept` returns distance_sq <= kLegibleRangeCells * kLegibleRangeCells, the same disc test sight uses, so a cell is legible exactly when its whole-cell distance is within 6. LookReport gains `bool legible;` that look_at sets from it. No other change to look_at
- test (after PEO-120): tests/core/test_look.cpp gains a case: on a hand-built open grid with sight range well past 6, look_at reports legible for (6,0), (0,6), (4,4) (distance_sq 32) and the player cell, and not legible for (7,0), (5,5) (distance_sq 50) and (6,1) (distance_sq 37)
- core (after PEO-008 and PEO-116): peo/core/look_label.hpp + src/core/src/look_label.cpp, one concept: what a thing shows from a distance, from content alone. `enum class ThingKind : std::uint8_t { Item, Container, Sign };` and `struct FarLabel { <PEO-008 item handle> label; ThingKind kind; };` `[[nodiscard]] FarLabel far_label(const <PEO-008 registry>&, <PEO-008 item handle> archetype) noexcept;` Rules, in order, all read from resolved content: (1) features.readable with kind = sign: Sign, label is the archetype itself; (2) features.container or compartments: Container, label is the topmost non-abstract item on its parent chain (itself when it has none); (3) otherwise Item, label is the topmost non-abstract item on its parent chain (claw_hammer -> hammer, skipping an abstract tool_base above it). The frontend shows the label's content `name` (the base name, without brand, modifier or detail name parts, which need examining). Never returns a compartment name, a purpose, a desc or contents. The chain walk is bounded by the registry's ancestry limit; no allocation, no I/O, same input same output
- test (after PEO-008 and PEO-116): tests/core/test_look_label.cpp, TEST_SUITE("look_label"), unit tier, against a fixture content tree under tests/data/look_label/ loaded through PEO-008's loader (or its in-memory builder): tool_base (abstract) -> hammer -> claw_hammer gives Item and hammer for claw_hammer and for hammer; an item with no parent labels as itself; a cabinet with compartments named by purpose gives Container and the cabinet, never a compartment; a jug with features.container gives Container; a sign with features.readable kind = sign gives Sign and itself; a note with features.readable kind = note is an Item (only signs read at range). Fixture names are test data only, not game content
- core (after PEO-050): the look report carries things. LookReport gains `std::array<ThingSight, kMaxLookThings> things; std::uint8_t thing_count; std::uint32_t things_total;` with `kMaxLookThings = 8` (a technical cap on what one report lists; things_total still counts all) and `struct ThingSight { FarLabel far; bool labelled; std::string_view sign_text; };`. look_at takes the World's per-cell item view that PEO-050 provides (as a parameter, keeping look_at off World as PEO-120 set it) and the registry; for each thing on the cell up to the cap: labelled = report.legible; when labelled, far = far_label(...) and, for a Sign, sign_text is the instance's rolled readable detail text from content (read through PEO-050, which resolves name and details from the seed); when not labelled, far is left default and sign_text empty, so nothing past range leaks a label. Unseen cells still return nullopt. No allocation
- test (after PEO-050): test_look.cpp cases with the look_label fixture content and items placed by hand through PEO-050's API: a claw_hammer 6 cells away reports labelled with label hammer; the same at 7 cells reports one thing, unlabelled; a sign at 3 cells reports its rolled text, at 7 none; a cabinet holding a hammer reports one thing (the cabinet), not its contents; nine things on one cell report thing_count 8 and things_total 9
- core: beyond 20 ft, per D-053 (wait for the answer in decisions.md). Answer A: nothing to build; past 6 cells things stay unlabelled. Answer B: whatever size rule D-053 B records, as one more constexpr function in look.hpp beside legible, read from content dims, with test cases at its boundary
- app (after PEO-050): fill look_line in src/app/main.cpp. It returns the content `name` of each labelled thing's label and, for a sign, its sign_text, verbatim from content, joined by a named separator constant; unlabelled things and an empty report give an empty view (the HUD keeps kKeyHints, as PEO-120 left it). Add no article, verb, count word or other text: the owner writes the look line's wording (D-042) and will replace this format; say so in the comment. The returned view points into a buffer App owns and reuses (no allocation per frame)
- docs: docs/architecture.md 'Current code' gains `look_label.hpp  far_label: what a thing shows from 20 ft (PEO-121)`; docs/domains/presentation.md lists D-053 under Decisions and moves PEO-121 from Queue to Done when completing
