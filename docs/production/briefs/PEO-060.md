# PEO-060 · Speculate the Dead's seconds to the next update: 512x512 with 50k Dead back under 1 ms commit (D-021, D-031)

## Goal

Per D-021 and D-031. PEO-058 made the Dead run live in commit, and 512x512 with 50,000 Dead now commits in 1.37 ms median (max 1.43 ms) on the M1 Air, over D-021's 1 ms. Between updates the Dead read only the last update's scent and nothing the player does between updates reaches them (the player is not in occupied_, deposits land at the next update). So everything the Dead do from one update to the next, the 9 s poll included, is fixed the moment an update commits and can be computed ahead on the worker, like the scent sweep. Commit then only replays recorded moves.

## Context

- PEO-058 report (commit d129f04): the cost is the poll (a strongest_neighbour test for every unit every 9 s) plus the per-second decisions.
- src/core/src/world.cpp dead_second, poll, advance, finish_from; Speculator in the app runs speculate() on a worker.
- Ryan's direction: exhaust algorithmic approaches and spread load across updates before touching mechanics. D-031's rules (slots, decide then land, reserved and vacated tiles) do not change.

## Units

- core: Speculation gains the Dead's timeline for the seconds (U, U+1] of the next update: per second, the moves that land, plus any poll result it needs; built from the committed state in speculate(), with no allocation once warm (reuse buffers like scent). Method is yours; recording landings per second and replaying them is the suggested shape.
- core: advance() with a valid speculation replays recorded seconds instead of deciding live; without one (a stale or missing speculation, a stage change) it runs dead_second live as now. The two paths must leave World::equivalent states.
- core: the speculation must be built after the committed update it depends on. If an update's speculation is requested before commit of the previous one finishes, fall back to live; do not guess.
- test: perf variants from PEO-043 report commit time including the replayed Dead seconds.

## Acceptance

- 512x512 with 50,000 Dead: commit max under 1 ms on the M1 Air (headless-release, pinned), speculate under 100 ms; 200x120 with 5,000 no worse than PEO-058's numbers
- commit(speculate()) and step() stay World::equivalent for mixed 1/3/6/12 s actions across many updates, and the pinned world hash is unchanged
- zero allocation after warm-up over 1000 mixed actions; suite under 1 s

## Tests

- tests/core/test_world.cpp: extend the golden and equivalence cases so every action length runs both paths and compares after each action, not only at boundaries
- a case where the speculation is stale (stage change mid-update) falls back live and still matches step()
