# PEO-079 · Flow-direction grid for the Dead's poll and decisions

## Goal

ScentWave keeps one direction byte per cell, written with each update, and the Dead's poll and calm decisions read it through flow_target(); every move is bit-identical to today's and a decision costs a fraction of the nine-cell scan

## Context

- docs/research/parallel-and-gpu.md section 3: the measured design (one byte per cell, age line checked at read time, 0.5-0.6 ms per saturated 512x512 update, decisions 60 -> 10 ns)
- src/core/include/peo/core/scent_wave.hpp: flow_target() is declared with its contract; src/core/src/scent_wave.cpp has a placeholder that computes it from the masks on every call
- tests/core/test_scent_wave.cpp 'flow_target equals strongest_neighbour on every open cell' pins the contract across tile borders, update, patch_deposit, and cold and warm sync_from; it passes against the placeholder and must keep passing
- src/core/src/world.cpp poll() and src/core/src/dead.cpp decide_move(): the two readers, today calling strongest_neighbour(pos, &blocked)
- Why the byte can drop the age line: sample() is max(stored - line, 0), which keeps the order of every value above the line; a neighbour below the line samples 0 and never beats the unit's own cell. So 'stored argmax over neighbours strictly above stored(from), first in kNeighbours8 order' plus 'stored(target) > line' at read time is exactly strongest_neighbour
- Between updates the field never changes (deposit_log runs immediately before update; patch_deposit runs at commit, at the boundary), so the bytes need refreshing only in update(), patch_deposit() and sync_from()

## Units

- test: before the readers switch (commit this first), pin a golden from today's code: a hash of every Dead's position after 60 updates of waiting and walking, on the town fixture and on a random walled stage with several thousand Dead. It must stay identical after the switch. The existing goldens ('the pre-clock world is pinned', 'commit(speculate()) is bit-identical to step()') must pass unchanged
- core: ScentWave gains a direction byte per cell (a sentinel for 'none'), sized in the constructor; flow_target() reads it, then checks the target's stored value against the age line. Keep the placeholder's answer as the test oracle until this unit's test is green
- core: update() refreshes the bytes once per update, after its rounds, over every tile any round changed plus their neighbour tiles (a cell's byte depends on its eight neighbours, so a change on a tile edge moves bytes one tile over). Same rules as the pull: open_ for orthogonals, diag_ for diagonals, no allocation per update, branch-free inner loop where it is cheap to make one
- core: patch_deposit() refreshes the bytes round the cells it raised (the deposit and its eight neighbours, so a 5x5 block of bytes); sync_from() brings the bytes over with the values: a full copy copies them, a partner sync recomputes or copies the bytes for each copied tile and its neighbour tiles
- core: poll() and decide_move() call flow_target(pos) instead of strongest_neighbour(pos, &blocked). decide_move keeps its signature (blocked becomes unused there; drop the parameter only if every caller and test changes with it in this unit)
- docs: docs/research/parallel-and-gpu.md section 3 gets a line saying it is built (PEO-079) with the measured numbers; scent_wave.hpp's flow_target comment loses 'placeholder' wording if any is left; the perf skill's numbers if they move
