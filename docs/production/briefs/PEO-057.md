# PEO-057 · Container purposes and three tags with may-appear tables (D-030)

## Goal

Per D-030: every compartment rolls a purpose from its seed (which picks its main loot and names it once examined, e.g. "cutlery drawer"), every container carries three tags (kind, context, detail) that each link to "may randomly appear" extras tables, and a Python reference roller in tools/content produces the same result for the same seed, so PEO-053 has an executable spec to port.

## Units

- content: new record type [purpose.X] { name (shown once examined: "cutlery drawer"), loot (ref: the main table), desc }. Add purpose to RECORD_TYPES in common.py and a schema in registry/schemas.toml. Each purpose implies the tag kind.X; register namespace kind as closed with lint deriving its members from the purpose records.
- content: register namespace ctx as closed with a first set: ctx.home, ctx.office, ctx.retail, ctx.food_service, ctx.medical, ctx.institutional, ctx.industrial, ctx.farm, ctx.lodging, ctx.vehicle, ctx.person. Every building record gets context = "ctx.X" (lint error if missing); a room may override it (a break room in a factory is still ctx.industrial, a staff kitchen in a hospital may say ctx.food_service). Nested containers and a person's pockets inherit the context of what holds them.
- content: register namespace detail as closed with a first set drawn from what generation already knows: detail.hobby.X for persona hobbies (woodworking, fishing, gardening, hunting, sewing, cooking, gaming), detail.trace.struggle, detail.trace.looted, detail.smoker, detail.gun_owner, detail.child, detail.elderly. A container gets at most one detail tag: from the room or object entry when authored, otherwise from the building's persona when PEO-014 lands (until then none).
- content: compartments (PEO-054) and room overrides replace loot with purposes = [{ purpose, w }], a weighted list; a single-entry list is allowed. Convert every loot hook PEO-054 created. Room overrides become purposes = { <compartment name> = [{ purpose, w }] }.
- content: first-pass purposes for homes, splitting today's tables rather than rewriting them: kitchen drawer (cutlery, utensils, junk, wraps_and_bags, towels), kitchen cupboard (dishes, glasses_mugs, cookware, food_storage, baking), pantry shelf, under_sink, medicine cabinet, bathroom vanity (toiletries, cleaning, linens), dresser drawer (tops, bottoms, underwear_socks, sleepwear, mixed), nightstand drawer, desk drawer (office_supplies, papers, personal), garage shelf (automotive, paint, garden, hardware, camping), and a maintenance_cabinet purpose used in office, retail, school and hospital rooms. The current kitchen_drawer table becomes the junk drawer. Keep each purpose's loot to items that exist.
- content: new record type [extras.X] { match = { kind?, ctx?, detail? } (every key given must equal the container's tag), chance_pct (the chance this table fires at all for a container), rolls, entries (same entry shape as loot) , why }. Author at least: one per home purpose for rare or useful finds; four negative or dangerous ones (a loaded pistol in a junk drawer at low odds, spoiled food, broken glass in a kitchen cupboard, an opened bleach jug under a sink); maintenance_cabinet by context (ctx.office: paper_ream, pen, marker, toilet_paper; ctx.retail: trash_bags, paper_towels, duct_tape, zip_ties; ctx.medical: latex_gloves, bleach_jug; any ctx: bucket, broom, work_gloves, flashlight, extension_cord); and one per detail tag listed above where an item fits (detail.smoker: cigarettes, lighter; detail.hobby.woodworking: chisel, wood_glue; detail.gun_owner: ammunition beside the drawer's other contents).
- tools: tools/content/generate.py, the reference roller. roll_container(db, seed, compartment, ctx, detail) returns { purpose, name, lines } where a line is { item, count, mods, substance, fill_pct, source }. Order and salts are the spec PEO-053 ports: purpose = weighted pick with hash(seed, 0, 0); main picks i = 1.. with hash(seed, 1, i) for the entry and hash(seed, 2, i) for the count; then for each tag in the fixed order kind, ctx, detail and each matching extras table in id order, fire with hash(seed, 3 + tag_index, table_index) < chance_pct, and its picks with hash(seed, 6 + tag_index, table_index * 256 + j). Picks that do not fit the remaining capacity (packed_dims, max_dim_mm, max_mass_g) are skipped; main loot rolls first, so extras never push out the main contents. No shared RNG stream anywhere.
- tools: lint: every purpose referenced exists; every compartment's purposes each fit it with loot_expected of main loot plus the expected extras of kind matches (the fit check from PEO-052, per purpose); every extras match names registered tags; every building has a context; every kind has at least one extras table or is listed in an allowlist with a why.
- test: tests/content/expectations or a new tests/content/rolls/*.toml read by test.py: a fixed seed on a kitchen_base_run top drawer in ctx.home rolls a known purpose and known lines (pin them once the content lands); the same seed rolls identically twice; rolling picks 1..k then k+1..n equals rolling 1..n (prefix stability); the same maintenance_cabinet seed in ctx.office and ctx.retail yields the same purpose and main lines but different extras.
- docs: content/README.md: the purpose and extras records with one example each, and the three tags; docs/design/gameplay-model/G02: one paragraph under D2.1 that a compartment's purpose is decided by its seed and revealed on examine (D-030).
