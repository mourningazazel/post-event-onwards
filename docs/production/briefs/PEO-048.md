# PEO-048 · Wind carries scent ahead outdoors; no wind indoors (D-020)

## Goal

Each stage has a regional wind, drawn from its seed, that makes scent steps cheaper downwind and dearer upwind and lets the front run up to `gust` extra cells downwind per update, scaled by a per-cell openness that is 0 indoors; with wind off every field, move and timing is unchanged

## Context

- D-020 and D-024 in docs/production/decisions.md; docs/design/scent-mobs.md 'Wind, indoors and out' and 'The transport: a geodesic field'
- docs/design/probes/probe3.cpp: the measured wind rule from the pathfinding review's section 8.1 (200x120, walker east, wind from the west: 0 cells ahead without wind, 59 ahead with 3 rounds downwind, 0 with openness 0). The probe uses floats and a push; the rule is restated below in the integer pull form
- The rule. Cost of a step from cell n to its neighbour i in direction d: max(1, C - wind_d x openness(n) / 255), where wind_d is an integer per direction, positive downwind, negative upwind, from the stage's wind (direction and intensity). An update runs `speed` rounds in all directions as today, then `gust` rounds in which only cells that changed in the previous round offer, and only along directions with wind_d > 0 and openness(n) > 0
- src/core/src/scent_wave.cpp pull_row(): the vectorised kernel. With two buffers, 'changed in the previous round' is cur[n] != other[n] on every pulled tile, and false on a tile nobody pulled (PEO-078's invariant), so the gust rounds need no extra state
- src/core/src/world.cpp finish_from() and the comment at speculate: patch_deposit is exact only for one round per update, and faster waves run the update live at commit. Wind with gust > 0 must not push commit onto that slow path (D-021: commit under 1 ms)
- D-021: integers only in anything that feeds back. The per-direction wind table is computed once per stage in integers (an integer angle and a fixed cos table, or a direction vector); no float in the update

## Units

- core: Stage gains `Grid<std::uint8_t> openness` (255 outdoors, 0 indoors, anything between for a porch or a broken wall later). generate_stage() fills it 255 on every open cell, so current stages are all outdoors. The test town fixture marks building interiors 0
- core: a Wind value (integer direction plus intensity, as a header in peo/core/) and its per-direction cost table; WaveParams gains `gust` (default 0) and an optional upward-loss term (cost added in proportion to intensity x openness, default 0). ScentWave learns openness the way it learns blocked: once, from the first grid it sees
- core: the kernel takes per-direction costs scaled by the sender's openness. Keep the current uniform-cost kernel as the fast path when the wind table is all zero, so a windless wave is bit-identical and no slower. Then the gust rounds
- core: patch_deposit() is exact for speed 1 plus `gust` downwind rounds: propagate the deposit locally through the same rounds with the same rules (a bounded block round the deposit), maxing into the field, and refresh what it raises. If it cannot be made exact, stop and write docs/production/handoffs/PEO-048.md rather than letting commit run live
- core: World draws the stage's wind from the stage seed (direction any angle, intensity in [0, WorldParams::wind_max]) and passes the table and openness to the wave. WorldParams::wind_max defaults to 0, so every existing test and golden is unchanged; the app sets a nonzero wind_max as configuration
- test: the probe's scenarios as doctests (see Tests), plus the patch oracle
- docs: docs/design/scent-mobs.md marks the wind rule built (PEO-048) with the measured numbers; docs/testing.md if a case lands in the scenario tier

## Acceptance

- ctest --preset headless passes (core, suite_budget, scenario_budget), nothing skipped or loosened
- With wind_max 0 (the default) every existing test, golden and perf line is unchanged, and the saturated 512x512 update is no slower than before (headless-release, report both)
- 200x120 open stage, player walks east one cell per update, wind from the west at full intensity: with gust 0 no cell ahead of the walker holds scent; with gust 2 scent reaches at least 20 cells ahead; with openness 0 along the path it reaches 0 ahead; scent behind the walker reaches the same distance in all three
- Upwind, a standing source's scent reaches fewer cells than downwind, and the field stays a valid climb: a greedy strongest_neighbour walk from every reached cell arrives at the source
- patch_deposit() after update() equals deposit() then update() value for value with wind and gust 1 to 3, over random walled stages and random wind (the oracle test), so commit keeps using the speculation
- No allocation per update; the wind table is built once per stage; no float in update(), patch_deposit() or the kernel

## Tests

- tests/core/test_scent_wave.cpp: windless bit-identity against the current kernel (the existing reference push already pins it); the walker-ahead cases (no gust, gust, indoors); upwind shorter than downwind; greedy climb from every reached cell with wind
- tests/core/test_scent_wave.cpp: patch_deposit oracle with wind and gust 1-3 on random walled stages (scenario tier if over about 50 ms)
- tests/core/test_world.cpp: the same seed gives the same wind; wind_max 0 changes nothing (existing goldens)

## Manual

- With the app's wind_max set, walk downwind along a street with the Dead ahead of you: some should turn toward you before your trail could have reached them on foot; walk the same street upwind and they should not
- Inside a building the Dead behave as with no wind
- Perf observation: the update time with wind on, in a crowded street, against wind off; note both in the item

## Out of scope

- Weather that changes the wind over time, and local wind from events (a later item once weather exists)
- House-specific wall rules and inner-wall buildup (D-020 says they live outside the base transport; D-024 chose not to build them)
- Scent only near the player and sealed buildings (PEO-047)
- Threads or GPU for the gust rounds (PEO-080, PEO-081)
