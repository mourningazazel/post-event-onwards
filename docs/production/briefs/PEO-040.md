# PEO-040 · World clock: one-second ticks; actions carry durations (D-015)

## Goal

Per D-015. The world keeps a clock in game seconds. Scent and the Dead update on a fixed cadence, every 6 s by default, whatever the player does. Each Action carries a duration in seconds and lands between updates; the player's scent is logged per second on the tile occupied and applied at the next update. At the default durations (step 6 s, wait 6 s) every existing seed plays exactly as today, bit for bit, so this item changes how time is kept, not what the player sees. It is the base for running (PEO-041) and soak (PEO-038).

## Units

- test: BEFORE any core change, on current main, add 'the pre-clock world is pinned' to tests/core/test_world.cpp: a fixed 200-action script (steps in all four directions, walls, waits) on the small stage from kSeed, then an FNV-1a hash over player, stage_index, each Dead's position and cooldown counted in updates, and the scent bits. Pin the hash value printed on main. It must still pass unchanged after every later unit; after unit 3 the hash helper derives 'cooldown in updates' as cooldown_s / update period.
- core: time types and durations. types.hpp: `using Seconds = std::uint32_t;`. action.hpp: named kStepSeconds = 6 and kWaitSeconds = 6; Action gains `Seconds seconds`, set by the factories (Action::step(dir, seconds = kStepSeconds), Action::wait(seconds = kWaitSeconds)); World treats 0 as 1. WorldParams gains `Seconds update_period = kUpdatePeriodSeconds` (6), documented as the cadence of scent and the Dead; ScentParams and player_scent stay per update, so no retune.
- core: the clock. World keeps `seconds_` (game seconds on this stage), `updates_` (updates run) and an occupancy log: tile plus seconds, merged per tile in first-visit order, in a reused vector (no allocation after warm-up). step(action): apply the action at once (the player is on the new tile for the whole duration), then walk the duration forward; seconds up to the next update boundary are logged on the current tile, and at each boundary run one update: step_linear, then for each logged tile patch_deposit(tile, player_scent * s / update_period), then clamp_floor, step_horde, clear the log. When s equals the period the factor is exactly 1.0, which is what keeps walking bit-identical. After the action, if the player is on the exit, load the next stage; load_stage resets seconds_, updates_ and the log. turn() stays the count of actions (the HUD shows it); add seconds() and updates() accessors.
- core: the Dead in seconds. Dead::cooldown becomes `std::uint16_t cooldown_s` and speed becomes `std::uint16_t step_seconds`; spawning keeps the same rng draw and stores draw * update_period. step_dead(unit, scent, blocked, period): if cooldown_s > 0, subtract min(cooldown_s, period) and do not move; else move up the gradient and set cooldown_s = step_seconds. That reproduces today's timing exactly. A Dead moves at most once per update in this item; update World::equivalent for the new fields.
- core: speculation by update. Speculation's `turn` becomes `update` (the updates_ value it was made for). speculate() computes the next update with no deposit, as today. commit(spec, action): apply the action and log it; if no boundary is crossed, leave spec untouched and valid; at the first boundary finish that update from spec (patch every logged tile, clamp, then re-decide each Dead within kRepatchRadius of any logged tile, not only the player's), consume spec, and run any further boundaries in the same action with the plain path. A stale spec (other update or stage) still falls back to step().
- app: src/app/main.cpp requests a new speculation only when the world's updates() or stage_index() changed since the last request; otherwise the finished one stays in use. No other frontend change.
- test: add to tests/core/test_world.cpp: 'two 3 s steps share one update's scent' (after step(3 s) twice then an update, each of the two tiles got exactly half of player_scent before diffusion; check through a 1x-period comparison world or the deposit log, and that the summed deposit equals one walking step's); 'a 12 s action runs two updates' (updates() rises by 2, the Dead get two chances to move); 'an action that does not reach a boundary changes no scent and no Dead'; extend 'commit(speculate()) is bit-identical to step()' with a mixed script of 3, 6 and 12 s actions.
- docs: docs/architecture.md, where the turn loop is described: the clock in seconds, the update cadence, occupancy logging, and that speculation is per update (D-015). One paragraph.

## Acceptance

- the pinned pre-clock hash passes unchanged after the rework: default steps and waits play every seed exactly as before
- commit(speculate()) is bit-identical to step() for mixed 3, 6 and 12 s actions
- two 3 s steps in one update deposit half of player_scent on each tile and one update's worth in total; a runner never deposits more per second than a walker
- no allocation per action or per update after warm-up (the occupancy log is reused)
- 'speculate and commit at 200x120 with 5000 Dead' stays within 10% of its time on main (report both numbers from headless-release)
- the suite stays under 1 s (suite_budget passes)
