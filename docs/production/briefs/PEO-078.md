# PEO-078 · Scent field as a dense pull over active tiles

## Goal

ScentWave's update runs as a branch-free pull over active 128x8 tiles with two buffers, bit-identical to today's push on every update, at least 10x faster on a saturated field, and a warm speculate no longer copies the whole field.

## Context

- docs/research/parallel-and-gpu.md section 2: why the pull equals the push (a round is a max over round-start offers; values only rise), the tile rule, the measurements
- docs/research/spikes/parallel-fields/fieldbench.cpp: DenseWave is a working, verified sketch of the kernel, the 128x8 tile set and the tile-change tracking; port it, do not link it
- src/core/src/scent_wave.cpp and include/peo/core/scent_wave.hpp: the push this replaces; keep every public function and its contract
- src/core/src/world.cpp speculate(), finish_from(), commit(): the copy this removes and the swap it keeps
- docs/adr/0014-threads-and-gpu-compute-in-core.md: determinism rules; this item is single-threaded, PEO-080 adds the executor
- .agents/skills/cpp-core/SKILL.md and .agents/skills/perf/SKILL.md

## Units

- test: move today's push into tests/core/reference_wave.hpp (test-only, unchanged maths) and add a golden test that runs it beside ScentWave on random open stages and the PEO-035 town, speed 1 and 2, with a walking deposit and standing emitters, comparing values() after every update for 200 updates; it passes against the current code before anything else changes
- core: ScentWave keeps two value buffers, an open-cell mask and a 4-bit diagonal mask per cell (corner rule, PEO-044), and per-tile changed flags; update() runs speed rounds, each pulling the active tiles (changed last round, plus their 8 neighbours) from the current buffer into the other and flipping; deposit() and patch_deposit() mark their tile changed. Invariant to keep and assert in debug: on every tile not processed this round both buffers hold the same values
- core: the row kernel is branch-free (max over the four orthogonals, the masked diagonals, then accept if above the age line and the old value) so it vectorises; build that translation unit for x86-64-v3 with a baseline fallback chosen at run time (e.g. __builtin_cpu_supports); arm64 uses NEON as is. Integer only, so every path gives the same bits
- core: patch_deposit keeps its contract against the pull: raise the cell, offer to its open neighbours by max into the current buffer, and mark the touched tiles changed
- core: speculate stops copying: the Speculation's wave is the World's partner buffer (the swap in finish_from already exchanges them), so a warm speculate pulls the World's current buffer into it; when it is not the partner (first use, a stale speculation, a different stage or size) it falls back to a full copy as today. Track partnership with a generation number, not by comparing contents
- core: active_cells() becomes the number of cells in active tiles (document the change); no allocation per update once warm
- test: extend the perf cases (or PEO-070's peo_bench if it has landed) with a saturated case measured at steady state: 512x512 with 6 emitters per 1000 tiles, 80 warm-up updates, median of 40
- docs: scent-performance.md gets the before/after table from this machine and the Builder's; architecture.md notes the two-buffer field

## Acceptance

- python3 tools/verify.py --full passes; the existing scent_wave, town and world tests are unchanged and green, including the speculate/commit golden test
- The reference-wave golden test passes on every update of every case
- Saturated 512x512, 6 emitters per 1000 tiles: the scent update's steady-state median is at least 10x lower than before on the same machine (the spike measured 24x on the cloud container)
- A warm speculate copies no full field (shown by its time at 2048x2048 dropping by the copy's ~10 ms, or by a counter in a test)
- No heap allocation inside update(), patch_deposit() or a warm speculate()
