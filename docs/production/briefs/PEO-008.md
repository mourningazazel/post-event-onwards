# PEO-008 · Content loader: registry, materials, items, modifiers into runtime tables

## Goal

The game reads content/ at startup through toml++ into a Content registry in core: every record type kept by id, every item resolved through its parent chain exactly as tools/content/derive.py resolve_item does (deep merge, arrays replace, tags accumulate, abstract and why not inherited), with the lookups PEO-121 and PEO-092 need (item by id, name, parent, abstract, tags, features, any value by dotted path). A ctest test proves the resolved items match derive.py over the whole content tree. Derived capabilities (PEO-128) and modifiers with the baked variant table (PEO-129) build on this and are not part of it.

## Units

- chore: vendor toml++ v3.4.0 as the single header third_party/tomlplusplus/toml.hpp with its LICENSE beside it, compiled with TOML_EXCEPTIONS=0 so a parse failure is a returned error, not a throw; add a decisions.md line 'toml++, vendored' (why: no network at configure, as doctest; upgrade by replacing the header and noting the version). It is included only from .cpp files in src/core, never from a public header
- core: peo/core/content.hpp + src/core/src/content.cpp, one concept: content data loaded and resolved. `struct ContentSource { std::string_view path; std::string_view text; };` `struct ItemId { std::uint32_t index; }` (strong type, comparable). `class Content` owns everything it loaded (it copies or parses out of the sources; the sources may die after load). `struct ContentLoad { std::optional<Content> content; std::vector<std::string> errors; };` `[[nodiscard]] ContentLoad load_content(std::span<const ContentSource>);` Rules, ported from common.load: sources are taken in the order given; RECORD_TYPES are id -> record, MERGED_TYPES merge across files; the three load errors with the same wording as common.py, naming the source path; any error means no Content. Then resolve every item as resolve_item does, in index order sorted by id: deep merge (tables merge, arrays and scalars replace), tags = parent tags then own, first occurrence kept; abstract and (when the child has why) why are not inherited; an unknown parent or a cycle is a load error naming the chain. `inline constexpr std::uint32_t kMaxItemAncestry = 16;` a longer chain is a load error (today's content is depth 1). The implementation keeps resolved items as toml++ tables behind a pimpl; nothing from toml++ appears in content.hpp
- core: Content lookups, all const, noexcept where they cannot fail, no allocation after load: `std::optional<ItemId> item(std::string_view id)`, `std::size_t item_count()`, `std::string_view item_id(ItemId)`, `std::string_view name(ItemId)`, `std::optional<ItemId> parent(ItemId)`, `bool abstract(ItemId)`, `std::span<const std::string> tags(ItemId)` (or an equivalent view), `bool has(ItemId, std::string_view dotted_path)`, `std::optional<std::int64_t> int_at(ItemId, std::string_view dotted_path)`, `std::optional<std::string_view> string_at(ItemId, std::string_view dotted_path)`, and `bool has_record(std::string_view type, std::string_view id)` for the other record types. Dotted paths address tables by key and arrays by index (`dims_mm.0`, `features.readable.kind`). These are the generic reads later items build typed views on; add no typed view here that no current brief needs
- test: tests/core/test_content.cpp, TEST_SUITE("content"), unit tier, in-memory sources only (string literals in the test): a parent and child resolve with tables merged, an array replaced and a scalar overridden; tags accumulate parent first with duplicates dropped; abstract is not inherited; the child's why replaces the parent's, and a child without why keeps the parent's (as resolve_item); unknown parent, a two-item cycle and a chain over kMaxItemAncestry each give an error and no Content; a duplicate id across two sources names both paths; an unknown record type and a TOML syntax error each name their source; a merged type split over two sources merges; int_at, string_at and has read nested tables and array indices and return nullopt or false for a missing path or the wrong type; the same sources in the same order give identical results twice. Fixture IDs are test data only
- tool: tests/content_dump/content_dump.cpp builds peo_content_dump (headless, linked to peo::core, built with everything else so it never rots, like peo_geo): `peo_content_dump <content_dir>` reads every *.toml under the directory in sorted path order (std::filesystem; the tool may touch files, core may not), calls load_content, prints errors and exits 1 on any, else prints every resolved item as canonical lines `<item id>\t<dotted path>\t<value>`, items sorted by id, keys sorted, arrays by index, strings with \\, tab and newline escaped, integers in decimal, booleans true/false
- tool: tools/content/golden.py prints the same canonical lines from common.load and derive.resolve_item (same sort and escaping), and with `--engine <peo_content_dump>` runs both and diffs, printing the first 20 differing lines and the count, exit 1 on any difference. tests/CMakeLists.txt adds ctest test content_golden running it when Python3 is found (same pattern and skip message as suite_budget)
- app: src/app/main.cpp loads content at startup: read the *.toml files under the content directory in sorted path order (a small header-only helper in src/app shared with nothing else is fine; the dump tool keeps its own few lines), call load_content, and on any error log each with SDL_LogError and refuse to start, naming the directory. The directory defaults to a PEO_CONTENT_DIR compile definition set to ${CMAKE_SOURCE_DIR}/content and is overridden by `--content <dir>`. App keeps the Content for later items; nothing reads it yet. Log one line on success: item count and load time in ms
- docs: docs/architecture.md moves Content from 'Planned seams' to built (PEO-008) with content.hpp's one-line summary and the dump tool; docs/wiki/content.md replaces 'the loader is PEO-008' with how the game loads content and how content_golden checks it; docs/wiki/api-reference.md gains content.hpp; docs/wiki/build-and-test.md gains peo_content_dump and content_golden; docs/domains/items.md moves PEO-008 out of Queue
