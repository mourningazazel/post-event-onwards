# PEO-036 · Fetched SDL is 3.2.30, so platforms without a system SDL fall back to a 60 Hz redraw loop

## Goal

Every platform gets the event-driven idle loop from PEO-025: the SDL fetched when no system SDL exists is 3.4.x, so the 60 Hz fallback is no longer the Windows path.

## Context

- cmake/FindOrFetchSDL3.cmake (PEO_SDL3_TAG)
- src/app/main.cpp (kWaitEventMinVersion, kFallbackIterateHz)
- .github/workflows/ci.yml (frontend build caches SDL on the hash of FindOrFetchSDL3.cmake)

## Units

- build: set PEO_SDL3_TAG to release-3.4.16 (the newest 3.4 tag on libsdl-org/SDL at briefing, matching the system package the Builder already runs). A developer with a stale CMake cache must re-configure; say so in the report.
- app: keep the SDL_GetVersion() check and the 60 Hz fallback: a system SDL older than 3.4 can still be picked up by find_package. Update the comment so it no longer says the fetched SDL takes the fallback.

## Acceptance

- CI's frontend build (SDL3 from source) builds release-3.4.16 and passes
- win-dev builds and, idle for 15 s, the game uses near 0% of a core (report the number)
- no behaviour change on a machine with a system SDL 3.4

## Tests

- all existing suites (no core change)

## Manual

- win-dev: build, run peo 7, leave idle 15 s, report CPU from Task Manager; press keys and confirm the screen still updates at once

## Out of scope

- dropping the 60 Hz fallback
- moving SDL to vcpkg or another package manager
