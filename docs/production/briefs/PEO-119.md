# PEO-119 · Sight: 500 ft optical range in core (D-049)

## Goal

Core computes what the player can see: every cell within an optical range of 152 tiles (about 500 ft at 1 m, D-049, ADR-0013) round the player that walls do not hide, by integer symmetric shadowcasting into a reusable field, with the range a parameter so binoculars can extend it later; the frontend draws terrain, the exit, the Dead and the scent overlay only on cells seen now, so the view never shows more than sight even once zoom (D-050) can fit more than the range on screen.

## Units

- core: src/core/include/peo/core/sight.hpp + src/core/src/sight.cpp (add to the core library sources), namespace peo::core, one concept: the player's sight. Contents, each with a doc comment saying why:
    - `inline constexpr int kOpticalRangeCells = 152;` (500 ft at 1 m tiles, D-049, ADR-0013).
    - `struct SightParams { int range_cells = kOpticalRangeCells; };` the range hook: binoculars (later) hand compute a longer range; nothing else reads a range. Negative ranges are taken as 0.
    - `class SightField` with: `void compute(const Grid<bool>& opaque, Vec2i origin, SightParams params = {});` fills the field from scratch for an origin inside `opaque` (asserted); `[[nodiscard]] bool seen(Vec2i cell) const noexcept;` true only for a cell computed as visible by the last compute, false for any other cell anywhere (outside the window, outside the grid, negative coordinates, or before the first compute); `[[nodiscard]] Vec2i origin() const noexcept;` and `[[nodiscard]] int range() const noexcept;` the last compute's inputs; `[[nodiscard]] CellRect window() const noexcept;` the square of cells the last compute could reach, origin +/- range clipped to the grid (a small struct {Vec2i min; Vec2i max;} inclusive, declared in sight.hpp), so a later map memory (D-051) can fold the seen cells into its own grid by walking only this window.
    - Storage: a byte buffer over the (2 x range + 1) square window, reused across computes; it grows only when a longer range is asked for and is never shrunk, so a move at the same range allocates nothing. Clear only the window used last time, not the whole buffer.
    - `opaque` is a parameter named for what it means to sight, not `blocked`: callers pass stage.blocked today, and when doors, windows or glass land, core can hand a separate sight layer without changing this API.
- core: the algorithm in sight.cpp, integer only (no float, so it is deterministic on every compiler, like the rest of core): symmetric shadowcasting over the eight octants (or four quadrants) from the origin, row by row outward, tracking visible sectors as start and end slopes held as integer fractions and compared by cross-multiplying. Rules, all pinned by the tests: the origin is always seen; a cell is seen only if dx*dx + dy*dy <= range*range (a disc, integer test); an open cell is seen when its centre lies within a visible sector (this is what makes sight symmetric between open cells); an opaque cell is seen when any part of it falls within a visible sector (so the walls that bound the room draw) and it shadows what lies behind it; cells off the grid count as opaque and are never seen. No recursion deeper than a fixed bound is required; an explicit row stack in a reused buffer is preferred over recursion so the cost stays predictable at range 152. Name every constant
- test: tests/core/test_sight.cpp (add to peo_core_tests sources), TEST_SUITE("sight"), unit tier on grids of at most 64 x 64: (1) open 21 x 21 grid (border cells open, not walls), origin at the centre, range 5: seen is true exactly for the cells with dx*dx + dy*dy <= 25 and false for every other cell of the grid and for (-1, -1) and (100, 100); (2) range 0 and a negative range: only the origin is seen; (3) a single wall two cells east of the origin in an open grid: the wall is seen, the cell directly behind it on the same row is not, and the cells beside the shadow are; (4) a closed 5 x 5 room of walls inside an open 31 x 31 grid with the origin inside: every room wall cell and every inside cell is seen and no cell outside the room is; (5) an L-shaped one-wide corridor of walls: the cells round the corner are not seen from the corridor's far end; (6) symmetry: on generate_stage of a small seeded spec (for example 64 x 36, wall_density 0.2, a fixed seed), for 8 open origins and range 12, for every open b seen from a, a is seen from b; (7) reuse: compute from origin A, then from origin B, equals a fresh SightField computed from B on every cell of the grid (no stale bits), and window() matches origin +/- range clipped to the grid, including an origin one cell from a corner; (8) the range hook: on an open 64 x 64 grid, range 10 then range 20 from the same origin, the second sees exactly the disc of 20 (the buffer grew), and a third compute back at 10 sees exactly the disc of 10 again
- test: in the same file, two cases tagged `* doctest::test_suite("scenario: sight")`: (9) range 152 on an open 401 x 401 grid with the origin at the centre: the count of seen cells equals the count of lattice points with dx*dx + dy*dy <= 152*152 (compute that count in the test with a plain double loop) and the four cells at exactly 152 along the axes are seen while 153 is not; (10) a `perf: sight, range 152` case tagged `scenario: perf` following test_world.cpp's perf cases: median of 50 computes from varied origins on an open 512 x 512 grid and on generate_stage at 512 x 512 with the game's default wall density, printing one `perf sight ...` MESSAGE line each in the format verify.py --perf collects
- app: src/app/main.cpp. App owns one `peo::core::SightField sight` plus the player cell and stage index it was last computed for (and a flag set by the 'n' branch after load_stage, so a new stage always recomputes even if the entry matches the old position). draw() recomputes it with world.stage().blocked, world.player() and default SightParams only when the player cell or stage index changed or the flag is set, never on a pure redraw (an expose or a scent toggle). In the map row loop, a cell that is in the stage but not `sight.seen` draws ' ' (dark, as off-stage cells do today); a seen cell draws exactly as today. The scent max pass and scent glyphs consider seen cells only, so the bands read relative to what is visible. The glyph lambda draws the exit and each of the Dead only when sight.seen(their cell); @ always draws. Keep the per-cell decision in one place in draw() (seen or not) so map memory (D-051 A) later adds a third, dimmed state there without restructuring. No new key, HUD text or log line: the HUD's `dead %zu` count is unchanged (D-042: no new player-facing strings)

- Check the exit `>` likewise shows only when in sight
- Toggle scent with [shift+s]: scent glyphs show only on seen cells and the bands still read (relative to the seen cells)

## Out of scope

- Map memory (cells seen before drawn dimmed): a follow-up pending D-051; the window() accessor and the single seen-or-not decision in draw() are the seam
- Binoculars, any item or key that changes the range: SightParams::range_cells is the only hook; no binocular content, action or UI
- Zoom (D-050): no change to map_cell_px or camera.hpp; the draw already limits itself to seen cells, which is what zoom needs
- The Look key and cursor (PEO-120) and labels within 20 ft (PEO-121)
- The Dead seeing the player, light, darkness, night or weather reducing sight, facing or cones
- Doors, windows, glass or any opacity layer other than stage.blocked; moving SightField into World or the save image (do that when a core mechanic, such as the Dead that can see, first reads it)
- Hiding the HUD's total `dead` count or any other existing HUD or debug text
