# PEO-050 · Items as seeds: read through the seed, instantiate on change, resolve on access, hidden container cap (D-023)

## Goal

Per D-023 and G03 (D3.2 to D3.4): the World holds items. Every thing has exactly one location, on a ground cell or in a compartment of a container thing, so nesting has no depth limit; a location lists its entries in order, each either a Thing (an instantiated record with a permanent 64-bit ID) or a Line (a nameless quantity of one archetype, D-026); a hidden per-location entry cap refuses new entries but never a line's growth and never crashes; the store is saved with its archetypes through CDIC, migrates on restore, and travels with an area. This is the data seam only: reading through the seed, instantiating on take and put-back are PEO-139, details and sign text PEO-140, time-driven resolve PEO-141, generation PEO-053.

## Units

- core: peo/core/item_store.hpp + src/core/src/item_store.cpp, one concept: where things are. `struct ThingId { std::uint64_t value; }` (comparable; 0 is none; IDs start at 1 and are never reused). `using Address = std::uint64_t;` (a generation address, G01 D1.5: given by generation or by hand, never interpreted here). `struct Location { enum class Kind : std::uint8_t { Ground, In } kind; Vec2i cell; ThingId container; std::uint8_t compartment; };` (cell set for Ground only; container and compartment for In only). `struct Thing { ThingId id; ItemId archetype; Address address; Location at; };` `struct Line { ItemId archetype; Address address; std::uint32_t count; std::uint16_t quality_mean; std::uint16_t quality_spread; std::uint32_t taken; };` with quality in permille (`inline constexpr std::uint16_t kQualityScale = 1000;`, PEO-013 may rescale) and `taken` the units already instantiated from it (PEO-139 uses it for the next unit's address; nothing here changes it). `struct Entry { enum class Kind : std::uint8_t { Thing, Line } kind; std::uint32_t index; };`
- core: the ItemStore class in the same header. `struct ItemStoreParams { std::uint32_t max_entries = kMaxEntriesPerLocation; };` with `inline constexpr std::uint32_t kMaxEntriesPerLocation = 4096;` and a comment: hidden, far above play (D-023), never shown. `enum class Placed : std::uint8_t { Ok, Full, NoContainer, NoCompartment, WouldNest, NoThing };` Operations, each changing nothing unless it returns Ok: `Placed place(const Content&, ItemId, Address, Location, ThingId& out)` (new Thing, next ID); `Placed place_line(const Content&, ItemId, Address, std::uint32_t count, quality mean, spread, Location)`; `Placed move(const Content&, ThingId, Location)`; `bool remove(ThingId)` (refuses a container with any entry in it); `void grow(Location, std::uint32_t line_index_in_listing, std::uint32_t by)` saturating at UINT32_MAX and never checking the cap; `void shrink(...)` to zero removes the line. Rules: an In location needs a container Thing whose archetype has compartments (count = length of the `compartments` array, probed with Content::has(`compartments.<i>`)) or features.container (count 1); compartment < count, else NoCompartment; a thing that is neither is NoContainer; moving a thing into itself or anything inside it is WouldNest (walk the container chain up, no depth limit); a location already holding max_entries entries is Full. Ground cells are not checked against the stage here (World does that)
- core: reads, no allocation: `std::span<const Entry> at(Vec2i cell) const` (the ground listing; a container's contents are never on the cell), `std::span<const Entry> in(ThingId, std::uint8_t compartment) const`, `const Thing* thing(ThingId) const`, `const Thing& thing_at(std::uint32_t index) const`, `const Line& line_at(std::uint32_t index) const`, `std::uint32_t compartments(const Content&, ThingId) const`. A listing keeps insertion order (D-026's put-back beside the quantity is an append, PEO-139). Storage is the Builder's call within: things and lines in dense vectors with free slots, a ThingId to slot map, listings keyed by a packed location key (no per-cell grid: stages reach 2048 squared); placing may allocate (an action, never per update), reads never do. Equality (`operator==`) compares contents, not storage layout, for World::equivalent
- core: World owns one ItemStore. `const ItemStore& items() const noexcept` and `ItemStore& items() noexcept` (for generation and tests; changes no clock; a speculation stays valid because the Dead and scent never read items). World checks a Ground cell is inside the stage before forwarding (a wrapper `Placed place(...)` on World, or a Placed::OffStage value: the Builder's choice, documented). load_stage and load_layout start with an empty store; AreaRecord gains `ItemStore items`, store_area copies it, resume_area restores it unchanged (aging is PEO-109 / PEO-141). World::equivalent compares it
- core: save. A new World-scope section ITEM (version 1): the next ThingId, every Thing (id, CDIC index, address, location) in ThingId order, every location's listing in order with each Line's fields inline (CDIC index, address, count, quality mean, spread, taken). CDIC is now written from the archetypes in use, one entry per distinct ItemId in ascending ItemId order (content_ref), so the same world gives the same bytes. Restore: every CDIC index in range, every container ID present, no cycle, every Ground cell inside the stage, no listing over max_entries, else Corrupt and the World untouched; with Content set, each CDIC entry resolves once (resolve) and every entry's archetype becomes the resolved ItemId (an entry that resolves to no item, which only test content without kJunkItemId allows, gives Corrupt naming the entry); MigrationReport::Line::references counts the things and lines that point at each entry. A thing whose compartment is past its container's resolved count moves to the container's last compartment, listed at the end, and this is noted in a SaveIssue (not refused). An image from before ITEM restores with an empty store
- test: tests/core/test_item_store.cpp, TEST_SUITE("items"), unit tier, against in-memory fixture content (as test_look_label.cpp does; names are test data only): tool_base (abstract) -> hammer; cabinet with two compartments; jug with features.container. Cases: (1) place a hammer on the ground: at(cell) lists it, ids 1, 2, 3 in order, a removed ID is not reused; (2) a hammer into cabinet compartment 1 lists under in(cabinet, 1) and not at(cell); compartment 2 is NoCompartment; into the hammer is NoContainer; (3) moving the cabinet to another cell keeps its contents and empties the old cell; (4) jug into cabinet is Ok, cabinet into jug is WouldNest; (5) with max_entries 3, a fourth place or place_line is Full and changes nothing; grow on an existing line passes the cap and saturates at UINT32_MAX without a crash; (6) a line and a thing in one location list in insertion order; (7) remove refuses a non-empty container
- test: tests/core/test_save.cpp gains cases: a World with ground things, a line, and nested containers saves, restores equivalent (World::equivalent) and saves to identical bytes; CDIC holds one entry per distinct archetype in ItemId order; restoring against content where hammer is gone resolves it to its nearest spawnable ancestor (fixture: tool_base made non-abstract in the second content, or a generic parent added), every thing keeps its ID and location, and the report's line counts its references; a CDIC index out of range, a missing container and a cell off the stage each give Corrupt with the World untouched. tests/core/test_revisit.cpp (or test_world.cpp where store_area is tested): store_area then resume_area keeps the store; load_stage of another stage empties it
