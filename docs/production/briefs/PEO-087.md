# PEO-087 · GPU wind and gust rounds fused in shared memory; direction bytes on the GPU under wind

## Goal

The GPU backend from PEO-081 also runs windy updates (wind cost table, openness, gust rounds) bit for bit with the CPU, and runs a whole update's rounds inside one dispatch by temporal blocking in shared memory, so the saturated windy field with emitters on most tiles is the case the GPU wins

## Context

- PEO-081: the backend seam, peo_gpu, the equivalence test and the lavapipe job. This item extends them; it adds no new seam
- src/core/include/peo/core/wind.hpp and src/core/src/scent_wave.cpp (wind_round, wind_offer, pull_row_wind, the gust loop near line 405): the reference. A full round takes offers from all eight neighbours with the wind step scaled by the sender's openness / 255; a gust round takes only downwind offers from open senders. Integers only, so the GPU matches exactly
- Temporal blocking (queue note on PEO-081, Ryan 2026-10-01): a workgroup loads its tile plus a halo of speed + gust cells of values, masks and openness into shared memory, runs every round of the update there, and writes back only the interior. Each round shrinks the valid region by one cell, so the halo is exactly the update's reach and the result equals one dispatch per round
- Direction bytes under wind (PEO-079 with PEO-048): the CPU picks the strongest neighbour on the final values; the GPU computes them in the same dispatch after the last round or in a second pass, matching the CPU's tie order
- Standing emitters (PEO-074 lever 3): a cell that emits every update need not be re-pulled once its neighbourhood is stable; measure first and add only if the profile says so

## Units

- gpu: upload the WindTable (eight steps and the downwind bits) and the openness bytes; a windy pull shader matching pull_row_wind, and the gust round
- gpu: a fused shader that runs speed full rounds then gust rounds over a tile plus a halo of speed + gust cells in shared memory and writes the interior values, tile flags and direction bytes. Keep the one-dispatch-per-round path from PEO-081 behind a switch so the two can be compared
- gpu: pick the workgroup tile size by measurement on the M1 and on lavapipe; name it as a constant with the numbers in its comment
- test: extend the GPU equivalence test with windy runs (several directions including diagonals, intensities up to kWindFull, gust 0 to 3, mixed indoor and outdoor openness), and with a wind change between updates; the fused and per-round paths compared with each other and with the CPU
- docs: research section 5 gets the measured windy numbers and the tile size choice
