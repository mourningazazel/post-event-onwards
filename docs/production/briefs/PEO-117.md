# PEO-117 · Player-centred scrolling view; stages bigger than the window

## Goal

The game window shows a view of the stage centred on the player that jumps one cell with every step, in whole cells sized to the resizable window with the leftover pixels as even dark letterbox bars, and the game's stage is bigger than the window (200x120 by default, `--stage WxH` to choose), so the screen follows the character instead of showing the whole test grid. The map layer's cell size is its own value, so zoom (D-050, later) changes one number. Frontend only: src/core has no diff. Decisions D-047 A + letterbox, D-048 A, D-049, D-050 (decisions.md, 2026-10-06).

## Units

- app: src/app/camera.hpp, header-only and SDL-free, peo::app namespace, one concept: which stage cells the window shows. Uses peo::core::Vec2i. All constexpr noexcept with doc comments, no allocation: struct View {int cols; int rows;}; struct ViewLayout {View view; int left_px; int top_px;}; layout_view(int px_w, int px_h, int map_cell_px, int hud_px) -> ViewLayout (whole map cells that fit below the HUD's hud_px, each count at least 1; left_px and top_px centre the grid, splitting the leftover pixels evenly into dark letterbox bars, top_px counted below the HUD). The map cell size is a parameter separate from the HUD's so a later zoom changes only map_cell_px (ADR-0003's per-layer cell size field); view_origin(Vec2i player, View view) -> Vec2i, the stage cell drawn at the view's top-left, player minus {cols / 2, rows / 2}, never clamped to the stage (D-049 A: the player is always on the centre cell, cells beyond the stage draw dark); view_to_screen(Vec2i cell, Vec2i origin, View view) -> std::optional<Vec2i> (the view cell, or nullopt when off view). Comment the even-size convention: with an even width the player sits on column cols / 2, one right of true centre
- test: tests/core/test_camera.cpp (add to peo_core_tests): layout_view(1280, 752, 16, 32) gives {80, 45} with zero bars; 1290 x 760 gives {80, 45} with left_px 5 and top_px 4; a size one pixel short of a cell rounds down; a map_cell_px of 32 halves the counts (the zoom path); a window smaller than the HUD still gives {>=1, >=1}; for odd and even views and for the player at a stage corner, the middle and beside each edge, view_to_screen(player, view_origin(player, view), view) == {cols / 2, rows / 2}; a cell one past each view edge is nullopt; an origin with negative coordinates (player near the top-left) is allowed. Two static_assert copies pin the constexpr contract
- app: the game's stage. Named constants kGameStageWidth = 200, kGameStageHeight = 120. game_params() sets stage_width/height from them, or from `--stage WxH` parsed in the existing argument loop (two whole numbers from from_chars around an 'x'; each in [kMinStageSide = 16, kMaxStageSide = 2048], the PEO-083 ceiling; anything else warns like --threads and keeps the default). initial_dead keeps today's density: kDefaultStageDead (40) * width * height / (80 * 45) in integer maths, named constants, so `--stage 80x45` plays exactly as today. Log one start line with the stage size and Dead count
- app: the window. Created with SDL_WINDOW_RESIZABLE at a default view of kDefaultViewCols = 80 by kDefaultViewRows = 45 map cells plus kHudRows, at kCell * kScale px a cell (today's size on the old default stage). SDL_SetWindowMinimumSize to kMinViewCols = 80 (the HUD lines are written to fit 80 columns) by kMinViewRows = 21 map rows plus the HUD. The window size no longer comes from the stage spec. App gains map_cell_px (doc comment: the map layer's cell, equal to the HUD's until zoom, D-050), set to kCell * kScale, which every map position uses instead of kCell directly
- app: draw(). Each draw reads the render output size (SDL_GetCurrentRenderOutputSize, divided by kScale, since the render scale is set first), calls layout_view with App::map_cell_px and the HUD's pixel height, then view_origin, and loops the view's rows and columns: a view cell whose stage cell is inside the stage draws its '#', '.' or scent glyph; outside it draws a space (the cleared dark background). Every map draw is offset by left_px/top_px, so the letterbox bars stay dark; the HUD lines stay at the window's top-left. max_scent is taken over the in-stage cells of the view only, so the scent bands read relative to what is on screen. The exit, the Dead and @ draw through view_to_screen and are skipped when off view; @ always lands on the centre cell. The row string is reused across draws (grow it only when the view widens, never per draw). HUD lines, colours, glyphs and key hints are unchanged (no new player-facing text, D-042)
- docs: docs/architecture.md, the 'Target system map' paragraph on the prototype's debug-text drawing gains one sentence: the window shows a player-centred view (src/app/camera.hpp, PEO-117) over a stage larger than it. docs/domains/presentation.md lists PEO-117; move it out of 'Queue' when completing

## Acceptance

- `python3 tools/verify.py --frontend` passes; ctest runs test_camera and it passes inside the 1 s unit budget; `git diff --stat` shows nothing under src/core
- In game, `peo` opens at today's window size on a 200x120 stage; @ sits on the centre cell of the map area and stays there on every step, walk or run, while the map moves under it

## Manual

- `cmake --build --preset dev && ./build/dev/bin/peo`: walk in all four directions; @ stays on the same screen cell and the map scrolls one cell a step. Hold an arrow at the 3/s cap and toggle run; scrolling keeps up without visible lag
- Walk to each edge and corner of the stage: @ stays centred, beyond the border wall is dark
- Drag the window bigger and smaller, and maximise it: more or less map shows in whole cells with even dark bars where it does not divide, @ stays centred, the HUD lines stay readable; it will not shrink below the minimum
- Toggle scent ([shift+s]) after walking a while: the * + : bands show over the view and change as it moves
- Press [n] a few times: each stage opens centred on its entry
- Run `./build/dev/bin/peo --stage 80x45`, then `--stage 1024x1024` and report whether turns still feel immediate at 1024 (the speculation spec:hit/miss on the status line); report bad --stage values' warnings
- Screenshot one view mid-stage and one at a corner for the report note
