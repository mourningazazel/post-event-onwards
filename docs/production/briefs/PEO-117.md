# PEO-117 · Player-centred scrolling view; stages bigger than the window

## Goal

The game window shows a view of the stage centred on the player that moves with every step, sized by the (now resizable) window, and the game's stage is bigger than the window (200x120 by default, `--stage WxH` to choose), so play reads like the real game: the screen follows the character instead of showing the whole test grid. Frontend only: src/core has no diff. Defaults D-047 A, D-048 A, D-049 A, D-050 A; if Ryan answers otherwise the Architect amends this brief before it is taken.

## Units

- app: src/app/camera.hpp, header-only and SDL-free, peo::app namespace, one concept: which stage cells the window shows. Uses peo::core::Vec2i. All constexpr noexcept with doc comments, no allocation: struct View {int cols; int rows;}; view_for_window(int px_w, int px_h, int cell_px, int hud_rows) -> View (whole cells that fit, map rows exclude the HUD rows, each at least 1); view_origin(Vec2i player, View view) -> Vec2i, the stage cell drawn at the view's top-left, player minus {cols / 2, rows / 2}, never clamped to the stage (D-049 A: the player is always on the centre cell, cells beyond the stage draw dark); view_to_screen(Vec2i cell, Vec2i origin, View view) -> std::optional<Vec2i> (the view cell, or nullopt when off view). Comment the even-size convention: with an even width the player sits on column cols / 2, one right of true centre
- test: tests/core/test_camera.cpp (add to peo_core_tests): view_for_window(1280, 752, 16, 2) == {80, 45}; a size one pixel short of a cell rounds down; a window smaller than the HUD still gives {>=1, >=1}; for odd and even views and for the player at a stage corner, the middle and beside each edge, view_to_screen(player, view_origin(player, view), view) == {cols / 2, rows / 2}; a cell one past each view edge is nullopt; an origin with negative coordinates (player near the top-left) is allowed. Two static_assert copies pin the constexpr contract
- app: the game's stage. Named constants kGameStageWidth = 200, kGameStageHeight = 120. game_params() sets stage_width/height from them, or from `--stage WxH` parsed in the existing argument loop (two whole numbers from from_chars around an 'x'; each in [kMinStageSide = 16, kMaxStageSide = 2048], the PEO-083 ceiling; anything else warns like --threads and keeps the default). initial_dead keeps today's density: kDefaultStageDead (40) * width * height / (80 * 45) in integer maths, named constants, so `--stage 80x45` plays exactly as today. Log one start line with the stage size and Dead count
- app: the window. Created with SDL_WINDOW_RESIZABLE at a default view of kDefaultViewCols = 80 by kDefaultViewRows = 45 map cells plus kHudRows, at kCell * kScale px a cell (today's size on the old default stage). SDL_SetWindowMinimumSize to kMinViewCols = 80 (the HUD lines are written to fit 80 columns) by kMinViewRows = 21 map rows plus the HUD. The window size no longer comes from the stage spec
- app: draw(). Each draw reads the render output size (SDL_GetCurrentRenderOutputSize, divided by kScale, since the render scale is set first), calls view_for_window and view_origin, and loops the view's rows and columns: a view cell whose stage cell is inside the stage draws its '#', '.' or scent glyph; outside it draws a space (the cleared dark background). max_scent is taken over the in-stage cells of the view only, so the scent bands read relative to what is on screen. The exit, the Dead and @ draw through view_to_screen and are skipped when off view; @ always lands on the centre cell. The row string is reused across draws (grow it only when the view widens, never per draw). HUD lines, colours, glyphs and key hints are unchanged (no new player-facing text, D-042)
- docs: docs/architecture.md, the 'Target system map' paragraph on the prototype's debug-text drawing gains one sentence: the window shows a player-centred view (src/app/camera.hpp, PEO-117) over a stage larger than it. docs/domains/presentation.md lists PEO-117; move it out of 'Queue' when completing

## Acceptance

- `python3 tools/verify.py --frontend` passes; ctest runs test_camera and it passes inside the 1 s unit budget; `git diff --stat` shows nothing under src/core
- In game, `peo` opens at today's window size on a 200x120 stage; @ sits on the centre cell of the map area and stays there on every step, walk or run, while the map moves under it

## Manual

- `cmake --build --preset dev && ./build/dev/bin/peo`: walk in all four directions; @ stays on the same screen cell and the map scrolls one cell a step. Hold an arrow at the 3/s cap and toggle run; scrolling keeps up without visible lag
- Walk to each edge and corner of the stage: @ stays centred, beyond the border wall is dark
- Drag the window bigger and smaller, and maximise it: more or less map shows, @ stays centred, the HUD lines stay readable; it will not shrink below the minimum
- Toggle scent ([shift+s]) after walking a while: the * + : bands show over the view and change as it moves
- Press [n] a few times: each stage opens centred on its entry
- Run `./build/dev/bin/peo --stage 80x45`, then `--stage 1024x1024` and report whether turns still feel immediate at 1024 (the speculation spec:hit/miss on the status line); report bad --stage values' warnings
- Screenshot one view mid-stage and one at a corner for the report note
