# PEO-025 · Frontend busy-loops: release build uses ~78% of a CPU core at idle

## Goal

The frontend does not busy-loop: release idle CPU is well under 25% of a core, with sim cadence unchanged.

## Context

- src/app/main.cpp
- PEO-001 report note (in WORK_QUEUE.json)

## Units

- app: stop the render loop from spinning. Prefer SDL vsync (SDL_SetRenderVSync(renderer, 1)) so present blocks to the display refresh; if unavailable or insufficient, cap the frame rate with a short sleep. Do not change the simulation tick interval (kTickMs).

## Acceptance

- release build idle CPU under 25% of one core (sample with ps/top while the window sits idle)
- sim tick pacing unchanged from the PEO-001 baseline (~10 ticks/s); no visible hitching

## Manual

- build release; run peo 7; leave the window idle 15 s and sample %cpu (ps -o %cpu / top) -> under 25% of a core; watch the tick counter -> still ~10/s, smooth

## Out of scope

- the turn-based/event-driven loop rewrite — that is PEO-002, which will make the loop wait on input and drive idle CPU near zero; PEO-025 is the immediate fix for the current real-time prototype and a simple vsync cap is expected to survive PEO-002
