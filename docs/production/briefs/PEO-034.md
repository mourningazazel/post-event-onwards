# PEO-034 · World accepts stage sizes and Dead counts that hang load_stage

## Goal

WorldParams that cannot produce a playable stage are caught in core instead of hanging: a stage smaller than 3x3, or more Dead than open floor cells, can no longer spin load_stage forever.

## Context

- src/core/include/peo/core/world.hpp (WorldParams)
- src/core/src/world.cpp (load_stage spawn loop)
- src/core/include/peo/core/grid.hpp (asserts are the core's existing precondition style)

## Units

- core: add a named minimum stage size (kMinStageSide = 3) next to WorldParams and document the precondition on WorldParams. In World's constructor, clamp stage_width and stage_height up to it; clamping keeps core free of exceptions and keeps every caller working.
- core: in load_stage, count the open cells other than the player's entry before spawning, and spawn min(initial_dead, open) Dead instead of looping until initial_dead placements succeed. The rng draws for the Dead that are placed must stay exactly as today, so existing seeds give the same horde (the golden and determinism tests guard this).
- test: tests/core/test_world.cpp gains 'a tiny stage is clamped to 3x3' (params 1x1 -> stage().spec is 3x3 and the World steps without hanging) and 'more Dead than floor spawns only what fits' (e.g. 6x6 stage, initial_dead 1000 -> horde().size() equals the open non-entry cells, and every Dead sits on an open cell).

## Acceptance

- no WorldParams value makes the constructor or load_stage loop forever
- for existing valid params, stage, horde and scent are bit-identical to before (golden test and 'same seed same world' unchanged and passing)
- the two new tests pass; the suite stays under 1 s

## Tests

- tests/core/test_world.cpp (two new cases)
- all existing suites

## Out of scope

- validating ScentParams
- a stage generator that guarantees entry-to-exit connectivity (PEO-005)
