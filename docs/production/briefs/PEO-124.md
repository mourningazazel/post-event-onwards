# PEO-124 · Map memory: seen terrain stays drawn dimmed (D-051)

## Goal

Cells the player has seen keep their walls and floor drawn dimmed once out of sight, with no Dead, the exit, scent or (later) items on them until seen again (D-051 A). Core gains a per-stage seen grid, MapMemory, owned by World for the stage in play: the frontend folds each fresh SightField into it (walking only SightField::window(), PEO-119), a new stage starts it empty, a stored area carries it and a resume brings it back, and World::save writes it as a Character-scope section so a restored game remembers what its player had seen. The frontend's single seen-or-not decision in draw() gains its third state: remembered, drawn as terrain in a dim colour.

## Units

- core: src/core/include/peo/core/memory.hpp + src/core/src/memory.cpp (add to the core library sources), namespace peo::core, one concept: what a character remembers seeing of the stage. `class MapMemory` with doc comments saying why: `MapMemory() = default;` (0 x 0, remembers nothing); `void reset(int width, int height);` all cells forgotten at that size (reallocates only when the size changes; same size is a fill); `std::size_t remember(const SightField& sight);` sets every cell sight.seen() reports, walking only sight.window() clipped to this grid, and returns how many cells were newly remembered (for tests and the perf line; no allocation); `[[nodiscard]] bool remembered(Vec2i cell) const noexcept;` false off the grid, at negative coordinates and on a default-constructed memory; `void mark(Vec2i cell) noexcept;` one cell, ignored off the grid (restore and tests use it); `width()`, `height()`, `[[nodiscard]] std::size_t count() const noexcept;` (cells remembered; kept as a running total so it is O(1)); `friend bool operator==` (same size and same cells). Storage: Grid<bool>. No reference to World, Stage or the player: it is one character's knowledge, so a second character later is a second MapMemory
- core: World owns `MapMemory memory_` for the stage in play. Public: `[[nodiscard]] const MapMemory& memory() const noexcept;` and `std::size_t remember(const SightField& sight);` which folds `sight` in and returns the newly remembered count, but folds nothing and returns 0 when sight.origin() != player() (a field computed before the last move or on another stage is stale; this is what keeps a frontend from smearing old sight onto a new stage). load_stage and load_layout (and so the exit branch of step) reset it empty at the stage size. store_area copies it into a new `MapMemory memory;` member of AreaRecord (revisit.hpp includes memory.hpp); resume_area takes it back when its size matches the rebuilt stage, else starts empty. step, commit and speculate never read or write it, so `commit(speculate())` stays bit-identical to step() with memory unchanged by both. World::equivalent also compares memory_ (so the save round-trip tests cover it). Update the doc comments of save(), store_area and AreaRecord to say what they now carry
- core: src/core/src/world_save.cpp, a new section `SEEN`, SyncScope::Character, version 1, written after CHAR. Payload: u32 count of characters (1 today, kCharacters), then per character: u32 stage index, i32 width, i32 height, then ceil(width x height / 8) bytes of row-major bits, cell i in byte i / 8, bit i % 8 (least significant first), padding bits zero. Restore: SEEN is optional (add it to `known` with Character scope, not to the required list): absent, as in every save written before this item, the restored World remembers nothing and no issue is added; present, it is read into a local MapMemory and refused as Corrupt, leaving this World untouched, when the count is not kCharacters, the stage index or size differs from the stage WRLD/STAG built, the payload is short or long, or a padding bit is set. kSaveFormat does not change (a new optional section is what ADR-0002's sections are for; an older build skips it as unknown)
- test: tests/core/test_memory.cpp (add to peo_core_tests sources), TEST_SUITE("memory"), unit tier, grids of at most 64 x 64: (1) a default MapMemory and one after reset(10, 8): remembered is false on every cell, at (-1, -1) and at (10, 8); count 0; (2) an open 21 x 21 grid with one wall, SightField range 5 from the centre: after remember, remembered equals sight.seen on every cell of the grid, the returned count equals count() and equals the number of seen cells; (3) a second compute from another origin, then remember: every cell remembered after the first fold still is (union), the return value is only the newly added cells, and remembering the same field twice returns 0 the second time; (4) the grid's data() pointer is the same before and after five folds (no allocation per fold), and reset to the same size keeps it while clearing every cell; (5) a field computed on a larger grid than the memory folds only the cells inside the memory (window clipped), no out-of-range write under the sanitizers; (6) World: after load_stage, memory() is the stage's size and empty; remember with a field computed at world.player() remembers the player's cell; remember with a field computed one cell away returns 0 and changes nothing; step onto the exit (or load_stage(next)) leaves memory empty at the new stage's size; load_layout likewise; (7) World: step and commit(speculate()) from equal worlds with equal non-empty memory give equivalent worlds whose memory is unchanged
- test: tests/core/test_revisit.cpp, one case: remember on a small generated stage, store_area, load another stage, resume_area(record): memory() equals the stored one; a plain load_stage of the same index remembers nothing. tests/core/test_save.cpp, three cases: (a) a World that has remembered cells saves a SEEN section with scope Character, restores into a fresh World with an equal memory(), and that World saves the same bytes (extend or sit beside the case at line 242); (b) the same image with SEEN removed restores Ok with an empty memory and no SEEN issue; (c) forged SEEN payloads (count 2, a width one larger, a stage index one higher, one byte short, one byte extra, a padding bit set) each give Corrupt, an issue naming SEEN, and leave the World's memory() and save bytes unchanged

## Out of scope

- Remembering the exit, items, signs or anything but walls and floor: D-051 A names walls and floor only; record a work item if wanted
- Fading or forgetting memory over time, or a remembered cell redrawn when the terrain changes out of sight (no terrain changes exist yet)
- A save file on disk, autosave or loading from the frontend: core's World::save and restore carry SEEN; the file on disk and its fallback copies are PEO-107's
- Stored areas in the save image: AreaRecord is in memory only today; when stored areas join the save (world scope, ADR-0017 decision 3), each record's MapMemory goes with it in the same SEEN payload layout, one entry per stored stage. Not built here
- Wiring store_area or resume_area into play (the 'n' key still loads the next stage fresh); PEO-109 and PEO-110 own revisits in play
- A map screen, map notes (Local scope) or revealing the map by any means but sight
- The Look cursor over remembered cells (PEO-120 limits it to seen cells per D-052 B; extending it is a separate item)
- Moving SightField into World: the frontend still computes sight and hands it to World::remember
