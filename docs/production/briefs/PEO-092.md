# PEO-092 · Content migration on load (ADR-0017)

## Goal

A save made before an item was renamed, split or removed restores against current content with every item reference resolved, in ADR-0017 order, to its remapped ID, else the nearest spawnable ancestor on its save-time parent chain still present (D-046: a removed claw_hammer becomes hammer), else junk that keeps the old name; resolution is a pure function of (save-time record, current content), and restore returns one report of what changed for the player to be told once.

## Units

- core: peo/core/content_migration.hpp + src/core/src/content_migration.cpp. struct ContentRef { std::string id; std::vector<std::string> ancestry; std::string name; } is what a save remembers of one item archetype: its ID, its parent chain nearest first, and its base name. enum class Migration : std::uint8_t { Kept, Remapped, StandIn, Junk }; struct Resolved { <PEO-008 item handle> item; Migration how; }; Resolved resolve(const ContentRef&, const <PEO-008 registry>&). Order: (1) the ID is present and not abstract: Kept. (2) the remap table maps it: follow remap to remap (bounded by the table size; a cycle or a target that is gone falls through) to a present, non-abstract item: Remapped. (3) the first entry of ancestry that is present and not abstract, each ancestor first passed through the remap table so a renamed parent still counts: StandIn. (4) the junk archetype: Junk. No allocation beyond the result; no I/O; same inputs, same output
- core: ContentRef for an item still in content is built from the registry (its ID, parent chain, base name) by a free function content_ref(<registry>, <item handle>), so World::save never hand-assembles ancestry
- core: struct MigrationReport { struct Line { std::string old_id; std::string old_name; Resolved to; std::uint32_t references; }; std::vector<Line> lines; } holds every entry that was not Kept, in dictionary order, and std::string migration_summary(const MigrationReport&) returns the one message the player is told, e.g. 'Since this save: claw hammer is now a hammer; 2 old things are now junk.' (empty string when nothing changed). Placeholder wording; the owner writes final text (D-042)
- core: save section 'CDIC' (World scope, version 1), the content dictionary: u32 entry count, then per entry the id, a u8 ancestry count and each ancestor nearest first, and the base name, all as ByteWriter length-prefixed strings. World::save always writes it (zero entries today: the World holds no item yet), so the format does not change when items land. The rule it fixes, written in the header comment: any later section that refers to content stores a u32 index into CDIC, never an ID string, so migration runs once per distinct archetype, not once per item, and the record's own fields (material, quality, contents) are untouched by it
- core: World::restore takes the content registry (as World already receives its executor) and a MigrationReport& it fills: it reads CDIC, resolves each entry once into an index-to-Resolved table that later sections will use, and counts references per entry (zero until items exist). Validation: an empty id, ancestry over kMaxAncestry = 16, a string over kMaxContentIdBytes = 64 (names kMaxContentNameBytes = 128), or a count past the bytes left is Corrupt naming CDIC and leaves the World unchanged, as PEO-091 does for its sections. An image without CDIC (none exist yet, but a PEO-091 build wrote one) restores with an empty report
- test: tests/core/test_content_migration.cpp, TEST_SUITE("content_migration"), added to tests/CMakeLists.txt, using a fixture content tree under tests/data/content_migration/ loaded through PEO-008's loader (or its in-memory builder, if it has one): tool_base (abstract) -> hammer -> claw_hammer, hammer_base_old renamed by remap, a remap cycle pair, and the junk archetype
- docs: docs/architecture.md 'Planned seams' Save entry gains CDIC and the index rule; docs/domains/persistence.md queue line drops 'deferred' and names PEO-092 as built

## Tests

- content_migration: an item still present resolves Kept to itself
- content_migration: a renamed item resolves Remapped to its new ID; a two-step remap chain resolves to the end; a remap cycle falls through to ancestry
- content_migration: a removed claw_hammer with ancestry [hammer, tool_base] resolves StandIn to hammer
- content_migration: a removed item whose nearest ancestor is abstract skips it to the next spawnable ancestor
- content_migration: a removed item whose parent was renamed resolves StandIn to the renamed parent
- content_migration: a removed item with no present ancestor resolves Junk, and the report line keeps its old name
- content_migration: content_ref of a present item gives its ID, parent chain nearest first, and base name
- content_migration: a hand-built image with a four-entry CDIC (Kept, Remapped, StandIn, Junk) restores Ok with three report lines in dictionary order and a one-line migration_summary naming them
- content_migration: CDIC with ancestry count over kMaxAncestry, and with a truncated string, is Corrupt naming CDIC and leaves the World unchanged
- content_migration: real content/ loads and every non-abstract item resolves Kept; removing claw_hammer resolves it to hammer (scenario tier if loading content/ exceeds the unit budget)
- All existing core cases, including PEO-091's save suite, still pass

## Out of scope

- Adding generic parents, the junk archetype and the remap record type to content/ and tools/content: PEO-116
- Showing migration_summary in game, and ADR-0002's warning before a lossy migration: the app's load path, PEO-107 (noted there)
- Item instances in the World and sections that store CDIC indices: whichever item lands them (PEO-053 onward) uses the index rule
- Migrating references to materials, modifiers, brands or other record types: remap only, when a section first holds them
- Splits that divide one old item into several new ones: a remap names the one ID the old record becomes
- Any change to the save container, fallbacks or compression (PEO-091, PEO-107, PEO-108)
