# PEO-095 · Geography square, 100 km (ADR-0018)

## Goal

peo::core can generate, from the world seed, any 100 km geography square whole at 100 m cells: ground elevation (so ranges and valleys), sea and coast, forests, and lakes with their outlines. Every cell is a pure function of the seed and its world cell coordinates, so neighbouring squares (D-041 A, endless) join without seams in any generation order. River courses are PEO-111; fitting towns to the map is PEO-096. A headless tool draws a square as an image for review. Nothing in game changes yet: stages do not read the map.

## Units

- core: peo/core/noise.hpp + src/core/src/noise.cpp (one concept: integer gradient-free value noise). inline constexpr std::int32_t kNoiseOne = 1 << 16 (Q16). [[nodiscard]] std::int32_t value_noise(Seed seed, std::int64_t x, std::int64_t y, int wavelength_log2) noexcept: lattice every 2^wavelength_log2 cells, corner values from one splitmix64 of (seed, lattice x, lattice y) mapped to [-kNoiseOne, kNoiseOne], blended with an integer smoothstep (3t^2 - 2t^3 in Q16) in x then y; lattice index is floor division by arithmetic shift (C++20 defines it), so the field is continuous across 0 and across any square edge. struct Octaves { int first_wavelength_log2; int count; std::int32_t gain_q16; } and [[nodiscard]] std::int32_t fbm(Seed, x, y, const Octaves&) noexcept: sum of octaves, each a halved wavelength and an independent seed (hash of seed and octave index), amplitudes multiplied by gain, normalised back to [-kNoiseOne, kNoiseOne]; [[nodiscard]] std::int32_t ridged(Seed, x, y, const Octaves&) noexcept: kNoiseOne - 2|fbm| style ridges for ranges. Write each worst case beside its type (int64 for intermediate products)
- core: peo/core/geography.hpp + src/core/src/geography.cpp, the terrain half. inline constexpr std::int32_t kGeoCellTiles = 100 (one cell is 100 m at ADR-0013's 1 m tiles) and kSquareCells = 1000 (100 km). struct SquareCoord { std::int32_t x; std::int32_t y; }; struct CellRect { std::int64_t x; std::int64_t y; std::int32_t width; std::int32_t height; } in world cells; [[nodiscard]] SquareCoord square_of(std::int64_t cell_x, std::int64_t cell_y) noexcept (floor division) and [[nodiscard]] CellRect square_rect(SquareCoord) noexcept. struct GeographyParams: every tunable named with its default and unit: sea_level_m = 0; continent Octaves and weight (first wavelength 2^11 cells, about 200 km, so coasts and seas span squares); range Octaves and weight through ridged(), times a low-frequency range mask so mountains come in bands rather than everywhere; hills Octaves and weight; elevation clamp to int16 metres; forest Octaves, forest threshold (Q16), treeline_m above which no forest grows, and a lower forest chance on steep or coastal cells if cheap; and the lake knobs of the next unit. constexpr bool valid(const GeographyParams&) checks ranges and the lake disc rule. struct TerrainSample { std::int16_t elevation_m; bool forest; } and [[nodiscard]] TerrainSample terrain_at(Seed world_seed, const GeographyParams&, std::int64_t cell_x, std::int64_t cell_y) noexcept: the point query; sea is elevation_m < sea_level_m (every such cell is sea, no inland basin test); forest only on land below the treeline. Each layer's seed is hash_u64(world_seed, kSalt<layer>, 0) with a named salt. Pick the defaults by looking at peo_geo output (manual): plausible coasts, a few ranges per few squares, forest in patches
- core: lakes, in geography.cpp. Lake sites on a jittered grid in world cells: GeographyParams lake_site_spacing_cells = 64 (6.4 km), lake_chance_q16, lake_seed_radius_cells = 8, lake_max_radius_cells = 24, lake_min_depth_m and lake_max_depth_m. One candidate per grid cell, jittered only within [max_radius, spacing - max_radius) of its cell so two lake discs never overlap (valid() refuses params that break this); its roll and jitter are hash_u64 of the site's grid coordinates. A site that rolls a lake: find the lowest terrain_at cell within the seed radius (ties broken by y then x); no lake if it is at or below sea level; level = lowest + a hashed depth in [min, max]; the lake is the 4-connected component of cells below level reached from the lowest cell inside the max-radius disc; if that component touches the disc rim or contains a cell at or below sea level, binary-search the level down in whole metres to the highest level whose component does neither; no lake if none. Everything uses terrain_at, never the square's own grids, so a lake straddling a square edge comes out identical from both sides. A region evaluates every site whose disc meets its rect
- core: struct WaterBody { enum class Kind : std::uint8_t { Sea, Lake } kind; std::uint64_t key; std::int16_t level_m; std::uint32_t cells; CellRect bounds; std::vector<std::vector<CellCorner>> rings; } with struct CellCorner { std::int64_t x; std::int64_t y; }. key is the lake site's hash, stable across squares; sea bodies are the 4-connected sea components inside the region (key 0, local to that region). rings: the body's outline as closed rings of cell corners in world cells, outer rings counter-clockwise and island holes clockwise, axis-aligned unit steps (no simplification); a sea ring that reaches the region edge runs along that edge. This is ADR-0018 point 2's polygons; PEO-096 bends streets along them
- core: struct GeographyRegion { CellRect rect; Grid<std::int16_t> elevation_m (ground, lake beds included); Grid<std::uint8_t> cover (bits kCoverSea = 1, kCoverLake = 2, kCoverForest = 4; value 8 kept for PEO-111's rivers, documented as reserved); Grid<std::uint16_t> body (0 none, else index + 1 into bodies); std::vector<WaterBody> bodies; [[nodiscard]] std::size_t bytes() const noexcept; }. [[nodiscard]] GeographyRegion generate_geography(Seed world_seed, const GeographyParams&, CellRect) and [[nodiscard]] GeographyRegion generate_square(Seed world_seed, const GeographyParams&, SquareCoord) (the region of square_rect). Pure functions: no globals, no I/O, no Rng stream; generation allocates (it runs once per square, not per update). The region fill may evaluate per row for speed, but every cell must equal terrain_at (a test pins it). A forest cell under a lake or sea is not forest. Lake body order is by site (y, x); sea bodies follow in scan order
- test: tests/core/test_noise.cpp TEST_SUITE("noise") and tests/core/test_geography.cpp TEST_SUITE("geography") with the full-square cases in TEST_SUITE("scenario: geography"), both added to tests/CMakeLists.txt (cases under Tests). The golden hash case is written last: generate, look at the peo_geo image for that seed, then pin the hash
- test: tests/geo/geo_dump.cpp, target peo_geo in tests/CMakeLists.txt beside peo_siege (headless, links peo::core only, file I/O allowed here and not in core). peo_geo --seed N --square X,Y [--span K] [--scale S] --out file.ppm: generates the K x K squares from X,Y, writes one binary PPM (P6) at one pixel per S x S cells (default 1 square at scale 1 = 1000 x 1000 px). Colours: sea darker with depth, lake a distinct blue, forest green, bare land on an elevation ramp with simple hill shading from the elevation gradient, and an optional --grid that draws square edges in one colour so seams can be checked. Prints per square: generation ms (wall clock, fine in a tool), bytes(), and the share of sea, lake, forest and land above 1000 m
- docs: docs/architecture.md gains a short 'Geography (ADR-0018, PEO-095)' subsection after 'Stages' (cells and squares, terrain_at as the source of truth, lake sites and the non-overlapping disc rule, what is not built: rivers PEO-111, towns PEO-096, neighbour residency) and adds noise.hpp and geography.hpp to the 'Current code' map; docs/design/world-generation.md 'Geography first' gains one line pointing at peo/core/geography.hpp; docs/testing.md names peo_geo as the headless way to look at a square

## Tests

- noise: value_noise is the same for the same inputs and differs when the seed changes; it stays inside [-kNoiseOne, kNoiseOne] over a 256 x 256 sample including negative coordinates
- noise: value_noise equals its corner value at every lattice point, and neighbouring cells differ by at most the bound one smoothstep step allows for that wavelength, across x = 0 and y = 0 as well (floor, not truncation)
- noise: fbm and ridged stay inside [-kNoiseOne, kNoiseOne] for the default Octaves
- geography: square_of and square_rect round-trip for cells at 0, 999, 1000, -1 and -1000
- geography: every cell of a 64 x 64 region equals terrain_at for its elevation and forest bit, and sea cells are exactly those below sea level
- geography: a region over the union of two adjacent 48 x 48 rects, one pair straddling the edge between squares (0,0) and (1,0) and one straddling cell (0,0), equals each part on every shared cell (elevation, cover, lake level by key)
- geography: with lake_chance at its maximum, every lake is 4-connected, lies inside its site's max-radius disc and off its rim, has every cell below its level and above sea level, and no two lake discs overlap; valid() refuses spacing below twice the max radius
- geography: a lake straddling a square edge (found by scanning sites near the edge under lake_chance at maximum) has the same key, level and cells from the region on each side
- geography: each body's rings are closed, step one cell along an axis, and their signed area (outer positive, holes negative) equals the body's cell count; body ids in the grid match each body's cells
- geography: a forest cell is never sea, lake or above treeline_m
- geography: a golden hash of the elevation, cover and body grids of a 128 x 128 region of seed 1 at cell (-64, 936) (it straddles x = 0 and the edge between squares (0,0) and (0,1)) is pinned, so a platform or compiler that changes one cell fails
- scenario: geography: generate_square(seed 1, (0,0)) has bytes() at most 8 MB and body ids consistent with cover bits
- scenario: geography: terrain_at sampled every 10th cell over a 4 x 4 block of squares for seeds 1, 2, 3 gives sea, forest-of-land and above-1000 m shares inside bands chosen from the peo_geo review, and at least one square with no sea and one with coast
- Not horde or scent mechanics: no peo_siege --check needed
- All existing core cases still pass

## Manual

- Nothing in game changes: build dev, run ./build/dev/bin/peo, walk through a stage exit, confirm play looks as before
- Run peo_geo --seed 1 --square 0,0 --out sq.ppm and peo_geo --seed 1 --square -1,-1 --span 3 --scale 3 --grid --out block.ppm (and seeds 2 and 3). Look for: coasts and ranges running across the square lines with no seam or step, mountains in bands with valleys between, lakes sitting in hollows and none on a slope or touching the sea, forest in patches that thins with height and never covers water. Tune GeographyParams defaults until it reads as land, then pin the scenario bands and the golden. Say in the note what you tuned and why
- Not a per-update path (no docs/bottlenecks.md row): a square generates once, far ahead of the player. Report generate_square ms and bytes() for one square in headless-release from peo_geo's output
