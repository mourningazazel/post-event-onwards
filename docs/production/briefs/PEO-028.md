# PEO-028 · Build sets no floating-point flags, so FMA contraction can break D-002 bit-identity

## Goal

The simulation produces bit-identical float results between Debug and Release and across architectures, as D-002 requires.

## Context

- cmake/CompilerOptions.cmake
- docs/production/decisions.md (D-002)
- docs/design/scent-performance.md
- src/core/src/scent.cpp

## Units

- build: set -ffp-contract=off for the core target (and /fp:precise on MSVC). gcc and clang default to -ffp-contract=fast at -O2, so 'here * share' and '(here - out + in) * keep' in ScentField::step may fuse into an FMA in Release and not in Debug, and differ between x86-64 and aarch64.
- test: pin the exact float bit patterns of a small ScentField after a fixed number of steps (reinterpret as uint32 and compare, not Approx). CI already builds g++-13, clang++-18 and release, so a divergence between those three will fail the test.

## Acceptance

- -ffp-contract=off (or the MSVC equivalent) is set for the core target
- a test pins exact float bit patterns after a fixed number of steps and passes identically on g++-13, clang++-18 and the release preset
- the numbers recorded in docs/design/scent-performance.md still hold

## Tests

- tests/core/test_scent.cpp (new bit-identity case)

## Out of scope

- converting the field to fixed point — that would be part of D-008 if it is answered that way
- any change to ScentField's algorithm
