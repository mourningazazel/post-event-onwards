# PEO-153 · Scent age line breaks in release past max_wave_updates; the one map's wave never resets: rebase it, bound the params, clamp deposits (PEO-077)

## Goal

The scent field stays correct for a whole game on the one map, whatever the tunables: the age line is rebased before it can leave int32, WorldParams' scent numbers are clamped so the bound is never short, and a deposit can never write a value a save would refuse.

## Context

- scent_wave.hpp:58-84 max_wave_updates, kMaxWaveUpdates (2^27 updates, about 12 game years at the defaults) and the comment 'A wave lives one stage (World::load_stage builds a new one)'. PEO-147 removes stage advance and PEO-149's recentre shifts the wave instead of rebuilding it, so after them one wave lives the whole game
- scent_wave.cpp:412 the only guard is `assert(updates_ < max_wave_updates(params_))`, compiled out in release. Measured by the Architect (headless-release, 2026-10-14, a 64x64 wave restored at the bound less 2): at updates = bound + 1 every unreached cell samples 2,147,483,640 and the next 2,147,483,632, so the whole map reads as the strongest scent there is and every Dead pulls toward nothing in particular
- The bound scales as 2^30 / age_cost (age_cost 8 now). The static_assert at :82 checks only the defaults; WorldParams::scent is not clamped anywhere in world.cpp, so age_cost 64 gives about 1.5 game years and 512 about 9 game days
- scent_wave.cpp:153 deposit: `age_line() + strength` with no clamp: a strength above params.strength writes a value restore() (:739-748) refuses as above the strongest deposit, so World::deposit (world.hpp:181, a test hook today; PEO-003 blood scent will deposit other strengths) makes a save that will not load, and a strength near INT32_MAX overflows the add
- desire.cpp:117-125 reads the line as int64 `age_cost * scent.updates()` and samples `values[i] - line`: it follows whatever ScentWave stores, so a rebase that keeps values and updates() consistent needs no change there; field_backend.hpp:35 FieldDispatch::age_line is copied per update, likewise
- world.cpp:425 logged_strength; :450 patch_deposit against `before.age_line()`; speculate syncs from the live wave (:610), so step and speculate must rebase on the same update
- The save writes SCNT values and updates (world_save.cpp); restore's bounds check stays as is and must accept every rebased state
- tests/core/test_scent_wave.cpp: the existing restore cases; tests/core/test_save.cpp:328-400 forged-section cases (`section(image, section_id(...)).payload`) are the model for injecting a late wave into a real-size World; tests/core/realsize_fixture.hpp from PEO-145

## Units

- core: ScentWave rebases its line. When an update would take updates_ to kRebaseUpdates (named in scent_wave.hpp: half of max_wave_updates(params), so a rebase always has a full half of headroom), it first subtracts age_cost x updates_ from every reached stored value in both buffers (cells at or below the unreached sentinel stay at it) and sets updates_ to 0; the patch buffers and the direction bytes keep their meaning because every comparison is against the line. An O(cells) pass once per kRebaseUpdates updates, no allocation. Replace the 'A wave lives one stage' comment with the rule. The assert stays as a backstop
- core: World clamps WorldParams::scent at construction (as it clamps sides today): strength in [1, kMaxScentStrength], distance_cost and age_cost in [0, kMaxScentCost], named in scent_wave.hpp with a why comment, chosen so max_wave_updates is at least 2 x kRebaseUpdates and the static_assert proves it for the clamped extremes, not only the defaults
- core: ScentWave::deposit clamps strength to [0, params.strength] before the add (in int64), so every value it writes is one restore() accepts. World::deposit's comment says so
- test: the cases under Tests
- docs: docs/wiki page that documents the scent age line and tunables (grep 'age line'): the rebase, the clamps and the deposit cap; architecture.md only if it repeats 'a wave lives one stage'

- A wave restored two updates below the bound and updated ten times samples 0 on every unreached cell and exactly what a fresh wave would on every reached one, in Debug and Release
