# PEO-123 · HUD lines clip when a tiling WM ignores the window's minimum size

## Goal

When a tiling window manager gives the window fewer than 80 columns (Hyprland ignores SDL_SetWindowMinimumSize: PEO-117's manual saw 609x750, 38 columns), the HUD's two lines word-wrap to the window's width instead of clipping at the right edge, and the map view moves down by the extra HUD rows. Method chosen: wrap, not truncate, because truncation would cut the key hints and the spec miss count the HUD exists to show. The wrapped text is the existing strings, split at their spaces: no new player-facing text (D-042). At 80 columns or more the HUD and the view are exactly as today.

## Units

- app: src/app/hud.hpp, header-only, constexpr, no SDL (like camera.hpp). `struct HudSpan { int begin; int length; };` and `[[nodiscard]] constexpr int hud_wrap(std::string_view line, int cols, std::span<HudSpan> out) noexcept`: greedy word wrap of `line` into rows of at most `cols` characters (cols below 1 counts as 1). A row takes as many whole space-separated words as fit; the spaces at a break are dropped (a row never starts or ends with a space); a word longer than `cols` is hard-broken at `cols`. Runs of spaces inside a row are kept as written (the status line's double spaces). Returns the number of rows the whole line needs, which may exceed out.size(); writes only the first out.size() spans. An empty line needs 1 row (an empty span). No allocation
- test: tests/core/test_hud.cpp, TEST_SUITE("hud"), added to tests/CMakeLists.txt beside test_camera.cpp. A static_assert that hud_wrap is usable at compile time. Cases on test strings only (not the game's strings): a line shorter than cols is one span covering it all; a line exactly cols long is one row; 'aa bb cc' at cols 5 gives 'aa bb' and 'cc' (break space dropped); a double space inside a row is kept, at a break both are dropped; a 7-letter word at cols 3 gives 3, 3, 1; cols 0 behaves as cols 1; an empty line returns 1; a line needing 4 rows with a 2-span out returns 4 and writes 2 spans; joining every span's text in order with the dropped spaces reproduces the words of the input in order (nothing lost or reordered) for a 70-character line at every cols from 1 to 80
- app: src/app/main.cpp draw() and App. HUD columns = out_w / (kCell * kScale). Wrap the status line and the second line (kKeyHints, or PEO-120's look line if it has landed) with hud_wrap into fixed std::array<HudSpan, kMaxHudLineRows> buffers (kMaxHudLineRows = 6, named, with a comment: enough for the 79-character status line down to 14 columns; rows past it are not drawn). Draw each span on its own HUD row at x 0, status rows first, in the existing colours. Draw a span's text without allocating: copy it into the reused `app.row` buffer (or another App-owned buffer) with its '\0', as the map rows do. HUD rows = status rows + second-line rows (each capped at kMaxHudLineRows). To stop the map jumping a row from one turn to the next as numbers in the status line grow, App keeps `hud_rows` and the HUD column count it was computed for: when the column count changes, hud_rows is recomputed; otherwise it is max(hud_rows, rows needed now). Pass hud_rows * kCell * kScale to layout_view and use hud_rows in the map's `top` in place of kHudRows
- app: keep kHudRows (2) and kHudPx as the HUD at 80 columns or more, used only for the window's default and minimum sizes; rename or comment so it is clear they are the wide-window HUD, not the drawn one. The status buffer stays char[80]
