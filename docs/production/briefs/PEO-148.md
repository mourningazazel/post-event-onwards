# PEO-148 · Map memory and ground items keyed by world cell, kept across windows (PEO-118)

## Goal

What the player has seen and every thing on the ground are keyed by world cell, not by window: going elsewhere on the map and coming back finds both as left, and AreaRecord carries only the Dead and their clock.

## Units

- core: MapMemory remembers by world cell. It keeps one 32x32-bit block per chunk with a seen cell, in chunk order (a sorted vector or std::map: the Builder's call), and the dense window grid it has today as the cache folds and draws use. `reset(width, height)` becomes `place(WorldCell origin, int width, int height)`: the window's cells go back into blocks (a chunk gets a block only when a cell in it is seen), then the grid is filled from the blocks for the new window. remember(sight) and remembered(Vec2i) stay window-local and allocation-free over known chunks; new remembered(WorldCell) reads the window or the blocks; count() counts every remembered cell. A first sighting of a chunk may allocate its block
- core: World keeps one MapMemory across windows: load_window and resume_area call place(), never forget; AreaRecord loses memory
- core: Location::cell is a WorldCell (ground only); ItemStore keys ground listings by WorldCell and at() takes one; World::place_item, place_line and move_item take world cells and refuse a ground cell outside the window as OffStage (doc: outside the resident window). One store for the whole map, kept across load_window; AreaRecord loses items
- core: save. SEEN writes the window grid as today, then every block sorted by chunk (two i64 and 128 bytes each); ITEM writes ground cells as two i64. Bump kSectionVersion and refuse older sections as PEO-147 does
- test: the cases under Tests; test_item_store and the World item cases at world cells, negative ones included; test_revisit drops memory and items from AreaRecord and asserts they survive anyway
- app: draw and peek keep reading remembered(Vec2i); any read past the window uses remembered(WorldCell)
- docs: architecture.md's tree lines for memory.hpp and item_store.hpp; docs/wiki persistence page
