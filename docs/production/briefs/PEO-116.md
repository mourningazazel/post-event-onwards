# PEO-116 · Content: generic parent archetypes for item families, a junk archetype, remap records (D-046)

## Goal

content/ gains what PEO-092 and PEO-121 read: a [remap.X] record type for renamed or split item IDs, loaded by both content loaders and linted; one inert, never-placed junk archetype; and a plain spawnable generic parent for the first eleven item families (claw_hammer -> hammer), added so that no existing item's resolved data changes. The remaining families are PEO-130.

## Context

- docs/domains/items.md (this item's domain page); content/README.md 'Directory layout' and 'Item record' (parent deep-merge: tables merge, arrays and scalars replace, tags accumulate parent first)
- docs/production/decisions.md D-046: a removed item becomes the nearest spawnable ancestor on its parent chain; item families gain a plain generic archetype as parent
- Consumers, read only their PEO-116 lines: PEO-092 (resolve: Content::remap, kJunkItemId, a removed claw_hammer resolving to hammer against real content/) and PEO-121 (far_label: claw_hammer labelled hammer)
- Why a generic parent must add nothing to its children: resolution deep-merges, so any table key, part, feature, array or tag on the parent that a child does not set itself is inherited and changes that child (its loot placement through from.* tags, which modifiers apply to it). Checked 2026-10-13: every existing plain item (pliers, axe, safe, desk, flashlight, glass_bottle) would leak parts, salvage or from.* tags into its would-be children, so no existing item becomes a parent here

## Units

- content: register the remap record. content/README.md 'Directory layout' gains `remaps/` holding `[remap.X]`; a 'Remap record' section: `[remap.old_id]` with `to = "<item id>"` (required string: the one ID the old record becomes; a split names one) and `why` (required). The key is an item ID that no longer exists; `to` may name another remap (chains follow; PEO-092 resolves them). content/remaps/remaps.toml holds a header comment and no records today. tools/content/common.py RECORD_TYPES gains "remap"
- core: src/core/src/content.cpp kRecordTypes gains "remap" (so a remap file is no longer an unknown record type). content.hpp gains `[[nodiscard]] std::optional<std::string_view> remap(std::string_view old_id) const noexcept;` the `to` of [remap.old_id], or nullopt when there is none or `to` is not a string; one step, no chain following (PEO-092 follows chains); no allocation. And `inline constexpr std::string_view kJunkItemId = "junk";` with a comment: the archetype an item resolves to when nothing else is left (D-046, PEO-092); load_content does not require it, so test fixtures need not carry one; lint requires it in content/
- test: tests/core/test_content.cpp, TEST_SUITE("content"), in-memory sources: a [remap.old] to = "new" record loads with no error and remap("old") gives "new"; remap of an ID with no record gives nullopt; a remap whose `to` is an integer gives nullopt; has_record("remap", "old") is true
- tool: lint.py gains lint_remaps, called from run(): a remap key that is a current item ID, a missing or non-string `to` or `why`, a `to` that names neither an item nor a remap, and a chain that cycles or ends at an abstract item are each an error naming the remap. And lint_junk: item.junk exists, is not abstract, has no parent, no features, no compartments, no capabilities and no from.* tag, and no room, loot, outdoor set or profile names it (an error each). lint_reachable does not warn for junk, nor for an item that is the parent of an item it does not warn for (a generic parent is reached through its children)
- test: tools/content/test.py gains run_remap_probes beside run_extras_probes, same pattern: each of a remap to a missing ID, a two-remap cycle and a remap keyed by a current item ID is refused by lint; a valid remap from a made-up old ID to claw_hammer is accepted. Wire it into main()
- tool: golden.py gains `--unchanged-from FILE`: FILE is an earlier print of its canonical lines; for every item ID in FILE, any line of that item now added, removed or changed is a difference, except an added `parent` line and `tags.N` lines when the item's set of tag values is the same; prints the first 20 differences and the count, exit 1 on any; items new since FILE are listed by ID and are not differences. Before the first content change below, save `python3 tools/content/golden.py > <scratch>/before.txt` from origin/main
- content: content/items/misc/junk.toml holds [item.junk]: name "junk", one composition part of an existing generic material, a small plausible size and mass, a glyph that exists, desc and why as placeholders (D-042: the owner writes final text), tags limited to what lint_junk allows. It never spawns; it stands in for an item whose archetype and every ancestor are gone (PEO-092)
- content: generic parents, each a new item in the file of its first child, its ID the plain noun, its children gaining `parent = "<id>"` and nothing else: hammer (claw_hammer, sledgehammer); saw (handsaw, hacksaw); knife (kitchen_knife, hunting_knife, utility_knife, cleaver); ladder (extension_ladder, ladder_step); lantern (battery_lantern, kerosene_lantern); radio (emergency_radio, walkie_talkie); computer (laptop, desktop_pc); battery (battery_9v, battery_aa, battery_d); wire (baling_wire, copper_wire); rifle (hunting_rifle, semi_auto_rifle); handgun (pistol, revolver). The rule for each generic, so it adds nothing to a child: it sets only dotted paths every child also sets (arrays count as one path; its composition parts are only parts every child has: hammer head and handle, saw blade and handle, knife blade, ladder rails, lantern body and globe, radio case and speaker, computer case, battery cell, wire wire, rifle barrel, handgun barrel, frame and internals, checked 2026-10-13), its tags are a subset of every child's (no from.* tag no child shares), and it names no modifiers, details, contents or salvage unless every child sets the same path. Its own values are a plain member of the family: real dimensions and mass that pass lint's density check, the shared parts' materials, a glyph a child uses, placeholder desc and why. If a family cannot meet the rule and still pass lint, leave it out, say which in the report note, and add it to PEO-130's notes
- check: `python3 tools/content/golden.py --unchanged-from <scratch>/before.txt` passes (only parent lines and tag order differ on existing items; the 11 generics and junk listed as new); lint 0 errors 0 warnings; test.py passes with rolls/pinned.toml unchanged
- docs: content/README.md gains 'Generic parents and junk (D-046)' (the add-nothing rule above, that a family's generic is its plain noun and is never placed by generation, and what junk is for), under its word cap; docs/wiki/api-reference.md content.hpp entry gains remap and kJunkItemId; docs/domains/items.md lists PEO-116 and PEO-130 in Queue, and moves PEO-116 to done when completing

- Content migration itself (PEO-092) and labels at range (PEO-121)
