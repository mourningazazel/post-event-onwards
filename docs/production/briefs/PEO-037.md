# PEO-037 · Cap turn input at 3 per second so holding a key never builds up lag

## Goal

Per D-011 the player takes at most 3 turns a second from the keyboard. A turn key pressed or auto-repeated sooner than 1/3 s after the last accepted turn is dropped, not queued, so releasing a held key stops the player at once.

## Context

- docs/production/decisions.md (D-011)
- src/app/main.cpp (SDL_AppEvent, take_turn)

## Units

- app: in src/app/main.cpp add a named tunable kMaxTurnsPerSecond = 3 and derive the minimum interval from it (no bare 333). In SDL_AppEvent, before take_turn, compare event->key.timestamp (SDL nanoseconds) with the timestamp of the last accepted turn; if the interval is shorter, ignore the press. Applies to every key that spends a turn (steps and waits), since both advance the Dead equally; Shift+S, N and Escape are never throttled. Keep the check to a comparison and one stored timestamp: no queue, no timer, no thread.
- docs: one line in docs/architecture.md where the frontend's turn loop is described, naming the cap and D-011.

## Acceptance

- holding a movement key moves the player 3 cells a second, give or take one, and it stops the moment the key is released
- tapping faster than 3 a second drops the extra taps; nothing is replayed later
- the speculation HUD still reads spec:hit at human speed
- src/core is unchanged

## Tests

- all existing suites (no core change)

## Manual

- Tap a movement key as fast as possible for 3 s: the turn counter rises by about 9, and no moves continue after you stop.
- Shift+S and N still respond instantly while a movement key is held.

## Out of scope

- a settings menu for the cap
- animation between cells
- any change to World or the turn model
