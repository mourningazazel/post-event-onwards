# PEO-075 · peo with a non-numeric seed aborts: std::stoull throws uncaught

## Goal

`peo abc`, `peo -5` and an out-of-range number start the game on seed 1 with a logged warning instead of terminating

## Context

- src/app/main.cpp SDL_AppInit: `seed = std::stoull(argv[1]);` throws std::invalid_argument or std::out_of_range, uncaught
- src/app stays thin: parsing a command-line number is frontend work, and the fallback is a constant (kDefaultSeed), not a magic 1

## Units

- app: parse argv[1] with std::from_chars into Seed; on any failure (no digits, trailing characters, out of range, a leading minus) SDL_Log a warning naming the argument and use kDefaultSeed

## Acceptance

- `peo abc`, `peo 12x`, `peo -5` and `peo 99999999999999999999999` each start on seed 1 and log one warning
- `peo 42` starts on seed 42 as before; `peo` with no argument starts on seed 1
- python3 tools/verify.py --frontend passes

## Tests

- None headless: the parse lives in the frontend. If it is factored into a pure function, put it in src/app and do not move it into core

## Manual

- Run each of the five command lines in Acceptance; the game window opens every time and the log shows the warning for the bad ones

## Out of scope

- Other command-line options
