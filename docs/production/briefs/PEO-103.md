# PEO-103 · Siege suite over its 10 min CI budget after ADR-0016 doubled updates per game hour

## Goal

The manual siege workflow runs the full matrix as three parallel jobs, one per building, each checking its own share of the baseline with peo_siege --building X --check, and no job takes longer than 10 min on the x86 runner. Nothing is cut: same 3 buildings, 3 setups, 2 densities, 2 seeds, 141x141, 48 h.

## Context

- docs/domains/dead.md (Tests line: the siege suite is on demand only)
- docs/testing.md: the Siege suite row and 'When to run the siege suite'
- Real number (Architect, 2026-10-06, actions run 37494258700 on main after PEO-090): the --check step took 704 s on ubuntu-latest x86, the whole job 12 min 13 s (setup and build about 25 s); --check passed, so the x86 and arm64 baselines still agree. 704 s replaces the 920 s projection; it is over the 600 s budget PEO-088 set
- Every building runs on the same 141x141 stage (siege_layouts.hpp: kStageSide) with 12 runs each (3 setups x 2 densities x 2 seeds), so a third of the matrix should take about 235 s on x86
- tests/siege/siege.cpp: the header comment (usage), main() argument parsing and the '(check || write) && filtered' refusal, the report builder (Firsts table and per-building sections), the maps builder, and the write/check block at the end
- tests/siege/baseline/report.md and maps.txt (the committed baseline, one file each for the whole matrix today)
- .github/workflows/siege.yml (one job today; the wall-time echo never runs when peo_siege fails, because the step shell is bash -e)

## Units

- test: peo_siege writes one report and one maps file per building: <out>/<B>/report.md and <out>/<B>/maps.txt, each holding only building B's configurations (the report header, B's rows of the Firsts table, B's section; B's maps). The baseline moves to tests/siege/baseline/<B>/{report.md,maps.txt} the same way; delete the old single-file baseline in the same commit. --check and --write now accept --building (any subset) and act on that subset's files only; --setup, --density and --seeds stay refused with --check and --write, so a check is always a building's full share. Results stay indexed by configuration, so a building's files are byte-identical whether it ran alone or in the full matrix. Rewrite the baseline with --write and say in the commit that no value moved: the old and new files differ only in the split headers and the Firsts table being split by building. Update the usage comment and the usage string
- ci: siege.yml becomes a matrix job over building [A, B, C] with fail-fast: false and timeout-minutes: 20; each job builds peo_siege, runs ./build/headless-release/tests/peo_siege --building ${{ matrix.building }} --out siege-out --check, echoes its wall time even on failure (capture the exit status with '|| status=$?' after setting status=0), and uploads siege-out/ as siege-report-${{ matrix.building }}. Keep workflow_dispatch the only trigger and keep the header comment's rule (on demand only, never on push or PR)
- docs: testing.md siege row and 'When to run' paragraph: the baseline is one pair of files per building; --building B --check checks one building's share (quicker locally); --write after a change rewrites all three unless filtered; the workflow runs the three in parallel. Point to PEO-103 for the split and record the 10 min per-job budget

## Acceptance

- peo_siege --check (no filter) matches the new per-building baseline on the M1 and exits 0
- peo_siege --building B --check exits 0 for each of A, B and C run alone, and their out/<B>/ files equal the full run's out/<B>/ files byte for byte
- peo_siege --setup enclosed --check and --seeds 1 --write still exit 2
- The baseline diff is only the split: every per-configuration table row and every map is unchanged
- The siege workflow, dispatched on main after the push, shows three jobs that all pass --check, and each job's peo_siege step prints a wall time under 600 s (expect about 235 s); the run id and the three times go in the report note
- verify.py passes; the 'siege layouts' fixture test is unchanged and still the only siege part in ctest

## Out of scope

- Cutting hours, buildings, setups, densities, seeds or the 141x141 stage: that changes N022's matrix and is the user's call
- PEO-082 (fast time passing in long waits): an L design item that batches updates and does not cut per-update work; not the lever here
- Any change to src/core or to the Dead's mechanics; any baseline value moving (if one moves, stop and report it)
- Running the siege suite on push, PR or in ctest (Ryan, 2026-10-02)
