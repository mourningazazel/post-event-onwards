# PEO-097 · Dwarf Fortress grid tileset loader (ADR-0015)

## Goal

`peo --tileset PATH` loads a Dwarf Fortress grid tileset (one PNG atlas of 16 x 16 square glyphs in code page 437 order, ADR-0015 point 3) and draws every layer with it: map, the Dead, the player, the exit and both HUD lines, all at the atlas's one cell size (ADR-0003). With no flag, or when the file is missing, is not a PNG, or is not a square atlas whose side divides by 16, the game logs why and runs in today's ASCII mode (SDL3's built-in debug font, D-042). No tileset is bundled or committed.

## Units

- app: src/app/glyph_atlas.hpp, header-only and SDL-free like thread_pool.hpp, peo::app namespace, one concept: the DF grid layout. Named constants kAtlasGlyphsPerSide = 16 and kTargetCellPx = 16 (the on-screen cell the ASCII mode already has: 8 px at 2x). Functions, all constexpr noexcept with doc comments: atlas_glyph_px(int width_px, int height_px) -> std::optional<int> (the glyph side, or nullopt when the atlas is not square, not positive, or its side is not a multiple of 16); atlas_cell(unsigned char cp437) -> a small struct {int col; int row;} (code % 16, code / 16); display_scale(int glyph_px) -> int (max(1, kTargetCellPx / glyph_px), so 8 px glyphs draw at 2x as today and 16 px or larger at 1x). No I/O, no allocation
- test: tests/core/test_glyph_atlas.cpp (add it to the peo_core_tests sources): atlas_glyph_px accepts 128x128 -> 8, 256x256 -> 16, 192x192 -> 12, and rejects 0x0, 100x100 (not a multiple of 16), 128x192 (not square), -16x-16; atlas_cell('@') is {0, 4}, '#' is {3, 2}, 0 is {0, 0}, 255 is {15, 15}; display_scale(8) == 2, display_scale(16) == 1, display_scale(32) == 1, display_scale(12) == 1. Add static_assert copies of two of these so the constexpr contract is pinned at compile time
- app: main.cpp parses `--tileset PATH` in the existing argument loop (a missing PATH warns like --threads does). Before the window is created, SDL_LoadPNG(PATH) loads the surface and atlas_glyph_px validates it; on any failure SDL_LogWarn says which (file unreadable or not a PNG with SDL_GetError(), or the size it got and that it needs a square atlas whose side divides by 16) and the game stays in ASCII mode. Guard the tileset path with `#if SDL_VERSION_ATLEAST(3, 4, 0)`; against an older installed SDL, --tileset warns that it needs SDL 3.4 and ASCII mode runs. The window's default and minimum sizes (PEO-117's kDefaultView*/kMinView* cells) are multiplied by the chosen cell (glyph_px or kCell) times its display scale, and sets App::map_cell_px to that cell size. After the renderer exists: SDL_SetSurfaceColorKey with magenta, SDL_CreateTextureFromSurface, SDL_SetTextureScaleMode NEAREST, destroy the surface; if texture creation fails, warn, fall back to ASCII and SDL_SetWindowSize and SDL_SetWindowMinimumSize to the ASCII sizes. App owns the SDL_Texture* (null in ASCII mode) plus the cell size and scale, and SDL_AppQuit destroys the texture before the renderer. Log one line at start naming the mode (e.g. 'tileset PATH, 16 px glyphs' or 'ASCII mode')
- app: draw() routes every glyph through one helper, e.g. draw_text(App&, int col, int row, std::string_view, Uint8 r, Uint8 g, Uint8 b): ASCII mode keeps today's SDL_RenderDebugText call at col * kCell, row * kCell under the existing render scale; tileset mode sets the texture's colour mod once per call and, per non-space byte, SDL_RenderTexture from the atlas_cell source rect to the cell's destination rect. The view's map rows, the glyph lambda (exit, the Dead, @ through view_to_screen) and both HUD lines use it, so text and map share the one cell size. kHudRows, colours, glyph choices and the redraw-on-dirty behaviour are unchanged. No per-draw allocation (the existing row string is reused)
- docs: docs/architecture.md, the 'Target system map' sentence on SDL_Renderer debug text gains that a DF-grid tileset can replace the font with --tileset (PEO-097, ADR-0015). docs/domains/presentation.md already lists PEO-097; move it out of 'Queue' when completing

## Acceptance

- `python3 tools/verify.py --frontend` passes (clang-format, warnings as errors, unit suite still under 1 s)
- `ctest` runs test_glyph_atlas and it passes; src/core has no diff
- In game, `peo` with no flag looks exactly as before (ASCII mode, same window size) and logs 'ASCII mode'
- In game, `peo --tileset <a 16 px DF-grid PNG>` draws the map, the Dead, @, > and both HUD lines from the atlas in their usual colours, one cell size throughout, at the default window of 80 columns x (45 map rows + 2) cells of 16 px, still centred on @ and still resizable down to PEO-117's minimum; an 8 px atlas gives the same window size as ASCII mode
- In game, `--tileset` given a missing path, a renamed non-PNG file, a 100x100 PNG and a 128x192 PNG each logs a warning naming the reason and runs in ASCII mode; none crashes
- No PNG, tileset or font is added to the repository (ADR-0015: no third-party tileset bundled; the owner supplies the default)

## Manual

- `cmake --build --preset dev && ./build/dev/bin/peo`: confirm the game looks and sizes as before and the log says ASCII mode
- Make a throwaway 16 px atlas outside the repo (any image editor: a 256x256 PNG, magenta background, a few glyphs drawn at the CP437 cells for # . @ d > and digits, e.g. '@' at column 0 row 4), or use a DF tileset you already own; never commit it. Run `./build/dev/bin/peo --tileset /path/atlas.png` and check the map, the Dead, @, > and the status and key-hint lines all come from the atlas, tinted, with no magenta showing, crisp (no blur) and aligned to one grid
- Repeat with an 8 px (128x128) atlas: the window matches the ASCII-mode size
- Failure paths: `--tileset /nope.png`, `--tileset README.md` copied to /tmp/x.png, a 100x100 PNG and a 128x192 PNG; each warns with its reason and plays in ASCII mode. `--tileset` with no path warns and plays
- Play a few stages ([n]) and toggle scent ([shift+s]) in tileset mode; the scent glyphs * + : draw from the atlas
- Perf observation: on the default stage hold an arrow key at the 3/s cap and toggle scent repeatedly in both modes; report whether tileset mode redraws without visible lag (redraws are on dirty only, so no tick budget is touched). If it visibly lags, say so in the report note rather than batching the draw here
- Walk to a stage corner and resize the window in tileset mode: @ stays centred and the view is whole cells of the atlas size

## Out of scope

- Bundling, drawing or committing any tileset or font (the owner supplies them, ADR-0015, D-042)
- A default tileset path, a config file or an in-game switch between modes; non-square-glyph (e.g. 8x12 curses) tilesets
- Glyphs beyond the printable ASCII the game draws today (box drawing, CP437 graphics), background colours per cell, Unicode mapping
- Batching the draw into SDL_RenderGeometry or moving to the SDL_GPU grid renderer (GAMEPLAN §2)
- Adding SDL3_image or any other dependency; changes to src/core
