# PEO-136 · Content: convert content/ to .peo and switch both loaders over (D-057)

## Goal

A one-time converter, tools/content/to_peo.py, writes the TOML content tree as .peo under the approved root tree (full-path references, dims { l, w, h }, unit-carrying numbers), and tools/content/peo_load.py reads a .peo tree back into the tools' Db (record type -> flat ID -> record, parents from header paths). golden.py --peo converts content/ into a scratch directory, maps the result back to TOML vocabulary with an independently written inverse, and proves every record of every type, and every resolved item, equal to the original. Python only: content/ stays TOML and neither core nor the game changes. Split (effort): the core loader is PEO-142, the switch of content/ and the tools to the new names is PEO-143; the title's 'switch both loaders' is theirs.

- PATH TABLE (Architect's call under the approved root tree's rule 'anything new goes under the umbrella it belongs to'): item -> item.<ancestors root first>.<id> (claw_hammer -> item.hammer.claw_hammer; no category segments yet, those are PEO-130); material -> item.material.<id> (D-055; still loaded as material records, not items, until PEO-130); substance -> substance.<id>; property, feature, capability, stimulus, namespace, fastener, scent, shape, schema -> def.<type>.<id>; tag -> def.tag.<id> (cat.ammo -> def.tag.cat.ammo); action, skill, modifier, detail_table -> mechanic.<type>.<id>; setting, building, room, purpose, loot, extras, outdoor_set, detail, detail_loot -> world.<type>.<id>; company, brand, store_chain -> brand.<type>.<id>; profile -> unit.human.<id> (PEO-133 may restructure); remap -> remap.item.<old id> in block form (keeps `why`). Merged tables become one record each: meta -> def.meta, status -> def.fastener_status, dominance -> def.scent_dominance (key D renamed d), default -> mechanic.reaction.default. A record's flat ID is its path after its type's prefix, except an item's, which is the last segment
- FIELD TABLE: a key ending in a unit suffix loses the suffix and its value carries the unit, longest suffix first so fuel_value_kj_g is not _g: _mm mm, _m m, _mm2 mm2, _m2 m2, _g g, _ml ml, _s s, _min min, _days d, _c C, _pct %, _mg_cm3 and _mg_ml kg/m3 (numerically equal). _kj_g, _w, _wh, _clo10 and every other key stay plain integers under their names (the parser has no such units). dims_mm = [a, b, c] -> dims { l = a mm, w = b mm, h = c mm }. A two-number list that derive or lint reads as low and high (count, fill_pct, size and the rest: list them from derive._range_mean and lint) -> a range. compartments = [ {name = ...}, ... ] -> compartments { <snake_case of name> { name = ..., ... } } in the same order; a room's purposes-override keys take the same snake_case. The same renames apply inside modifier op `path` strings and salvage `set` keys; an op's set or add value takes the unit of the renamed field; a mul value is a factor
- VALUE TABLE: integers stay; floats -> whole percent (0.35 -> 35%; refuse anything else); true/false -> yes/no; abstract = true -> the `abstract` keyword, abstract = false dropped; parent dropped (the header path says it); a string that lint treats as a reference -> a full path (tags -> def.tag.*, materials -> item.material.*, items, loot, purposes, modifiers, details, shapes, skills, ...); every other string stays a string: names, descs, glyph names, brand_cats (no record type yet), requirement strings like fasten>=2 (PEO-132 parses them). Word scales and prose stay as they are (PEO-137). A string holding a quote or a line break is written as """...""" with escapes; every other string verbatim
- docs/bottlenecks.md 'What counts': load runs once at startup; PEO-135 measured peo.py at ~588 ms per MB, so the 930 KB tree is a check, not a budget concern

## Units

- docs: docs/design/content-format.md gains a section 'Converting from TOML (PEO-136)' with the path, field and value tables from the context, the list of fields that became ranges and the list of reference fields by record type (both found while writing the converter). The tables are the contract PEO-142 and PEO-143 build to
- tool: tools/content/to_peo.py (stdlib only): `to_peo.py --out DIR [--content DIR]` loads with common.load and writes one .peo per TOML file at the same relative path, records in the file's order, fields in key order, block form with 4-space indent, a list on one line when it fits in 100 columns and otherwise one entry per line. Output is byte-identical run to run. It refuses, naming file, record and field, and writes nothing: a key that is not a grammar name after renaming, two keys that collide after a suffix is stripped, a float that is not a whole percent, a reference string naming no record, an ID that is not a valid path segment. Merged tables are written into the file they came from
- tool: tools/content/peo_load.py: `load(content_dir) -> common.Db` over *.peo, parsed with peo.py: record type and flat ID from the path table (longest prefix wins, so item.material.* is material); an item's parent is its header path minus the last segment when that names an item record, none when it is `item`, and an error otherwise; `parent` is stored as that parent's flat ID and `abstract` as True, so derive.resolve_item works unchanged. Values become plain Python: Integer and Quantity int (base unit), Range [low, high], Boolean bool, String and Expr str, Path a `Ref(str)` subclass holding the full path, List list, Block dict. Parse errors keep peo.py's file:line:col text; a duplicate path names both files
- tool: golden.py --peo [--content DIR]: runs to_peo into a temporary directory, loads it with peo_load, maps it back with back_to_toml(db) (written in golden.py from the docs tables, not by calling to_peo: suffixes and units back, ranges to lists, percents to floats, dims to a list, compartment blocks to a list, Refs to flat IDs, paths back to keys), then compares every record of every type and every merged table with common.load's, and every item after derive.resolve_item on both sides; prints the first 20 differences and exits 1 on any
- test: tests/content/peo_convert/ holds a small TOML tree that exercises every table row (a parented item, an abstract one, a material, a dotted tag, a compartment list, a range, a float, a modifier op on a suffixed path, each merged table) and its expected .peo output; test.py main() checks to_peo's output matches byte for byte, runs golden.py --peo over it and over content/, and checks each refusal on an in-memory bad record
