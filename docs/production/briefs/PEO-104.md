# PEO-104 · Status line shows the last speculate time (ms) beside spec:hit/miss, so the pool and --threads 1 can be compared in game

## Goal

The status line shows how long the last finished World::speculate() took, in milliseconds to the microsecond, beside spec:hit/miss (e.g. `spec:hit 0.277ms (miss 3)`), so the PEO-080 manual step 'compare speculate time, pool vs --threads 1' (left undone in PEO-101) and PEO-071/073 can read it in game. Frontend only: core is untouched.

## Context

- docs/domains/time.md (the speculation and executor rows)
- docs/architecture.md: 'Computing while waiting (PEO-007)' (speculate runs on the frontend's worker; M1 numbers 28-277 us at 200x120 with 5000 Dead, 0.1-1.5 ms at 512x512) and 'Turn model' (the ThreadPool, --threads N)
- src/app/main.cpp: class Speculator (run() calls world_->speculate(buffer_) with mutex_ released; busy_/ready_ are written under mutex_), struct App (last_hit, misses), take_turn(), and the status snprintf in draw() (char status[80], the 'Two lines, each under the default stage's 80 columns' comment)
- Wall time is I/O, so it belongs in the app, never in core (AGENTS.md: core has no clocks). Two std::chrono::steady_clock reads per speculate() are not per-tick or per-Dead work, so no docs/bottlenecks.md row is touched

## Units

- app: Speculator times each world_->speculate(buffer_) call in run() with std::chrono::steady_clock (start before, stop after, both outside the lock) and stores the duration in whole microseconds (std::uint64_t, named e.g. last_us_) under mutex_ in the same locked block that sets ready_. Add [[nodiscard]] std::uint64_t last_speculate_us() that reads it under the lock; 0 until the first speculate() finishes. In take_turn(), after quiesce() (the worker is idle then), copy it into a new App field (e.g. last_spec_us, doc comment: the speculate() that this turn's hit/miss refers to, or the last one to finish on a miss). draw() prints it between spec:%s and (miss %llu) as integer milliseconds and a three-digit microsecond fraction, "%llu.%03llums" from us / 1000 and us % 1000 (named constant for 1000, e.g. kMicrosPerMilli), so no floating point. No allocation, no new thread, no new lock beyond the existing mutex_. Update the Speculator's class comment to say it also times each run

## Manual

- `cmake --build --preset dev && ./build/dev/bin/peo` (default threads). Walk 20 steps, waiting a moment between keys so speculations hit; note the spec ms readings (a range, e.g. 0.08-0.30 ms). Confirm it shows 0.000ms only before the first speculation finishes, never afterwards
- Hold an arrow key so turns come at the 3/s cap; confirm the number keeps updating and the game does not stutter (the clock reads cost nothing visible)
- Restart with `./build/dev/bin/peo --threads 1` and repeat the 20 steps from the same default seed; note the range. Press [n] to reach a larger stage if one exists and compare both runs there too
- Perf observation: in the report note, give the two ranges (pool vs --threads 1) per stage tried, the thread count the pool used (logged at start: 'N thread(s) for the simulation'), and repeat both with `cmake --build --preset release && ./build/release/bin/peo` (say which preset each number is from)
