# PEO-127 · Look-ahead edge window on modifier+direction

## Goal

Outside Look, ctrl plus a movement key opens a strip along that edge of the map, the full edge long and 15% of the view deep, showing the cells just beyond the view on that side; ctrl plus the same key pushes it out half a strip further each press, ctrl plus a side key reopens it on that edge, ctrl plus the opposite key closes it. The strip follows the view as the player walks, draws by the same seen/remembered/unseen rule as the map, spends no turn and leaves queued taps alone (Ryan's design, notes 2026-10-10).

## Units

- app: src/app/peek.hpp, header-only, SDL-free, namespace peo::app, one concept: the look-ahead strip. Each item with a doc comment saying why:
    - `inline constexpr int kPeekDepthPercent = 15;` (Ryan's 'maybe 15%') and `inline constexpr int kPeekMinDepth = 1;`
    - `[[nodiscard]] constexpr int peek_depth(View view, Vec2i dir) noexcept`: the strip's depth in cells across its edge, `max(kPeekMinDepth, extent * kPeekDepthPercent / 100)` where extent is view.rows for a north/south dir and view.cols for east/west; integer maths, never more than extent
    - `[[nodiscard]] constexpr int peek_stride(int depth) noexcept`: `max(1, depth / 2)`, the half-strip each further press moves out
    - `struct PeekStrip { Vec2i at; View size; Vec2i origin; };` where it is drawn (`at`: the view cell of its top-left), its size in view cells, and the stage cell drawn at its top-left
    - `class Peek` with `[[nodiscard]] bool open() const noexcept;`, `[[nodiscard]] Vec2i dir() const noexcept;`, `[[nodiscard]] int steps() const noexcept;`, `void close() noexcept;`, and `bool press(Vec2i dir, View view, Vec2i view_origin, CellRect limit) noexcept;` taking a cardinal unit dir (asserted). press: closed, opens on dir's edge at steps 0; open on the same dir, steps + 1, unless that strip would no longer overlap `limit` (then nothing changes and it returns false); open on the opposite dir, closes; open on a side dir, moves to that edge at steps 0. Returns whether anything changed
    - `[[nodiscard]] std::optional<PeekStrip> strip(View view, Vec2i view_origin) const noexcept;` nullopt when closed. With d = peek_depth, k = steps * peek_stride(d), O = view_origin: north {at {0, 0}, size {cols, d}, origin {O.x, O.y - d - k}}; south {at {0, rows - d}, size {cols, d}, origin {O.x, O.y + rows + k}}; west {at {0, 0}, size {d, rows}, origin {O.x - d - k, O.y}}; east {at {cols - d, 0}, size {d, rows}, origin {O.x + cols + k, O.y}}. So at steps 0 the strip shows the d cells right past that edge ('starts one tile over'), and the stage cells it shows are always beside the view's own columns or rows. Stored as dir and steps, never as stage cells, so it follows the view as the player walks and survives a resize
    - No allocation, no SDL, no World. Add the header to the app's sources only if the CMake lists headers
- test: tests/core/test_peek.cpp (add to peo_core_tests beside test_camera.cpp), TEST_SUITE("peek"), unit tier, a few static_asserts for the constexpr contract like test_camera.cpp: (1) peek_depth: 15% of rows for north/south and of cols for east/west, rounding down, at least 1 on a 1x1 and a 5x5 view; peek_stride halves, at least 1; (2) a closed Peek has no strip; press opens on that edge at steps 0 and returns true; (3) the strip's at, size and origin for each of the four edges at steps 0 on an odd and an even view, and the origin is exactly one cell past the view's edge (north: origin.y + d == O.y; south: origin.y == O.y + rows; and so on); (4) a second press the same way moves origin out by peek_stride and nothing else; (5) a side press moves to that edge at steps 0; (6) the opposite press closes it and returns false from open(); (7) press stops (returns false, steps unchanged) when the next strip would lie wholly outside limit, and a strip that only touches limit's edge still counts as overlapping; (8) the same Peek with a moved view_origin gives a strip moved by the same amount (it follows the walk); (9) close() closes
- app: the keys, src/app/main.cpp. App gains `peo::app::Peek peek;` beside look. In SDL_EVENT_KEY_DOWN, after the Look branch and before L, Escape and shift+s: when `(event->key.mod & SDL_KMOD_CTRL) != 0` and look_dir_for(key) names a dir, ignore it if `event->key.repeat` (one half-strip per press, not a race to the edge), else call `peek.press(*dir, app->view, view_origin(player, app->view), app->sight.window())`, set dirty when it changed, and break. It never calls offer, clear, take_turn or the speculator, so a walk already queued plays on (Ryan: 'an eye forward as you walk'). Any other ctrl+key falls through as today. The n key (next stage) calls `peek.close()` with its other resets
- app: drawing the strip, src/app/main.cpp draw(). First lift the per-cell map loop (seen draws terrain or scent, remembered draws dimmed terrain, unseen draws nothing; then exit, Dead and @ glyphs) into one local lambda or static function taking a stage origin, a view-cell offset and a size, and use it for the main view with no change in output. Then, when `peek.open()` and not `look.active()` (Look already pans to any seen cell, and the strip would cover its cursor), take `peek.strip(view, view_origin(player, view))`, fill its rect with the background colour (SDL_RenderFillRect, so the main map under it is hidden), draw its cells through the same routine with the strip's origin, and outline its inner edge with a one-pixel line in a named colour (`kPeekEdgeRgb`) so the eye can tell it is not the map continuing. Scent, when on, uses the main view's max_scent so the bands read the same in both. The row buffers are reused: a strip is never wider than the view. A strip far out draws mostly dark or dimmed: it shows only what sight or memory already has (D-051), so it reveals nothing new
- docs: docs/architecture.md, the app part of 'Current code' (beside camera.hpp) gains `peek.hpp  Peek: the look-ahead strip on one edge of the view (PEO-127)`; docs/domains/presentation.md moves PEO-127 from Queue to Done when completing

## Manual

- `cmake --build --preset dev && ./build/dev/bin/peo`: press ctrl+up; a strip appears across the top with an edge line. Compare it with what the map shows after walking a few steps up: the strip's bottom row should be the row that appears above the old top row
- Press ctrl+up several more times: it moves out half its depth each time and stops once it is past sight; holding ctrl+up does not race it out (repeats are ignored)
- Press ctrl+right, ctrl+down, ctrl+left: each moves the strip to that edge, starting just past it; ctrl plus the opposite key closes it
- Open the north strip, tap up a few times quickly, then press ctrl+up mid-walk: the queued steps all play, the strip follows the view, the turn count rises only by the steps
- Press L with the strip open: the strip goes, the cursor works as before; L again brings the strip back
- Toggle scent (shift+s) with the strip open: the strip shows scent bands on its seen cells matching the map's
- Press n: the new stage starts with the strip closed
- Resize the window with a strip open: it keeps its edge and step and resizes to 15% of the new view
- Perf observation: on `--stage 512x512` with the default horde, walk with a strip open and say whether redraws feel any slower than with it closed

## Out of scope

- Any player-facing text: a key hint for ctrl+direction, labels in the strip (D-042, Ryan's words)
- Diagonal strips or corner windows: look_dir_for is cardinal only
- Several strips at once, a strip during Look, mouse control, rebinding the modifier (no settings system yet)
- Zoom or binoculars (D-050): the strip is in cells and takes the view, which is all they need
- Showing anything sight or memory has not given: the strip never widens what the player knows
- Any change to src/core, sight, Look or the save image
