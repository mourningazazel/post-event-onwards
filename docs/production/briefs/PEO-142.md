# PEO-142 · Content: core load_content reads .peo, parents from header paths (D-057)

## Goal

load_content reads .peo sources as well as TOML: a source whose path ends in .peo is parsed by parse_peo, its records typed and given flat IDs by PEO-136's path table, items parented from their header paths, and every item resolved on the parser's own PeoValue tree (TOML sources are adapted into it until PEO-143 deletes them). The Content API is unchanged and keeps flat IDs. peo_content_dump over a converted tree matches peo_load.py through golden.py line for line, so engine and tools read .peo identically before any content moves.

## Units

- core: content.cpp keeps resolved items as PeoValue blocks instead of toml::table: one merge (blocks merge by key, every other value replaces, tags are the parent's then its own without repeats, abstract never inherited) and one leaf walk on PeoValue. A TOML source is converted to PeoValue as it is read (integer -> Integer, float -> a Float leaf as today, bool, string, array -> List, table -> Block); that adapter is the only toml++ code left and PEO-143 deletes it. Leaves: Integer and Quantity are Integer leaves (base unit); a Range is two leaves `.0` and `.1`; String, Path and Expr are String leaves (a Path's full path); for_each_leaf keeps sorted keys and arrays by index
- core: a .peo source goes through parse_peo (its errors become load errors as written). Each record is typed and given its flat ID by the path table (longest prefix wins; an unknown root or type is an error naming file and line); an item's parent is its header path minus the last segment when that names an item, none under bare `item`, otherwise an error; the merged-table records fill the merged types. remap() returns the flat ID of the record its `to` path names. The same flat ID twice in one type is an error naming both files, whichever format each came from
- app/test: read_content_files takes the extension to read (`.toml` default, so the frontend is unchanged); peo_content_dump takes `--ext .peo`
- test: tests/core/test_content.cpp, TEST_SUITE("content"), new cases on in-memory .peo sources: a parent from the header path; a header whose prefix is not an item rejected; an abstract record; a quantity read through int_at in base units; a range as `.0` and `.1`; a Path read through string_at as its full path; remap of a path `to` gives a flat ID; tags concatenated without repeats; a duplicate flat ID across a .toml and a .peo source rejected naming both; item.material.* loads as a material (has_record) and not as an item
- test: ctest content_golden_peo: runs to_peo.py over content/ into the build tree, then golden.py --content <that dir> (reading through peo_load when the directory holds .peo) --engine peo_content_dump --ext .peo; golden.py gains that format switch. content_golden on TOML keeps passing
