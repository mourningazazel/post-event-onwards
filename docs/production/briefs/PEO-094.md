# PEO-094 · Lazy revisit catch-up (ADR-0019)

## Goal

peo::core keeps one clock since the Event across stages and can store an area and resume it later: on resume its horde thins to the attrition curve in closed form (one comparison per unit, the same work for a day away or ten years), and several short absences give exactly the state of one long absence of the same length. Player-made things aging is PEO-109; running catch-up as a streaming job on reload is PEO-110. Nothing in game changes yet: today's stages are never revisited.

## Units

- core: peo/core/aftermath.hpp (one concept: aftermath curves over the event clock). using EventSubsteps = std::uint64_t (substeps since the Event; u64 because u32 runs out at 34 years); inline constexpr EventSubsteps kSubstepsPerDay; inline constexpr std::uint32_t kAffectedScale = 65536; struct CurveKnot { std::uint32_t day; std::uint32_t affected; } (parts of kAffectedScale); struct Curve { std::array<CurveKnot, kMaxCurveKnots> knots; std::uint8_t count; } (kMaxCurveKnots = 8, no allocation); [[nodiscard]] std::uint32_t affected_at(const Curve&, EventSubsteps t) noexcept: piecewise linear in integer maths between knots, the first knot's value before it, the last knot's value after it (saturates, ADR-0011 point 2). Knots are strictly increasing in day and non-decreasing in affected; a constexpr valid(const Curve&) checks it and World clamps an invalid curve to the default
- core: inline constexpr Curve kDefaultAttrition, the Dead gone by each day since the Event, as proposals the owner can tune (ADR-0009 says its parameters are proposals; content data takes this over once content loads): day 0 none, day 7 5%, day 30 25%, day 365 70%, day 1825 85%, then flat. Each value a named constant with a comment pointing at the Aftermath table row
- core: Dead gains std::uint16_t fate, the unit's seeded attrition threshold (ADR-0009), in the padding: static_assert(sizeof(Dead) == 12). [[nodiscard]] std::uint16_t draw_fate(const Curve&, EventSubsteps at, std::uint64_t hash) noexcept in aftermath.hpp: uniform in [min(affected_at(at), 65535), 65535], so a unit that exists at `at` has not yet met its curve. load_stage and load_layout draw each unit's fate from hash_u64(stage seed ^ kFateSalt, unit index, 0) at since_event() after the reset; the Rng stream, positions and speeds are untouched, so every existing test and siege number is unchanged. The fate travels with the unit: Dead drawn in from elsewhere keep theirs (ADR-0019 point 3). World::equivalent compares fate too
- core: the event clock on World. WorldParams gains std::uint32_t start_day = 7 (play starts at the one-week preset, ADR-0009) and Curve attrition = kDefaultAttrition. World::since_event() -> EventSubsteps = start_day * kSubstepsPerDay + substeps run on every earlier stage + substeps(). load_stage and resume_area keep it running (the stage-local substeps() still resets as today); nothing else reads it yet. Attrition never runs while an area is loaded: a unit the player is watching does not vanish
- core: peo/core/revisit.hpp: struct AreaRecord { std::uint32_t stage_index; EventSubsteps updated_at; std::vector<Dead> horde; }; void thin_horde(std::vector<Dead>& horde, const Curve& attrition, EventSubsteps now): stable erase of every unit with fate < affected_at(now), survivors in their order. No dependence on updated_at: that is what makes repeated returns equal one long absence. World::store_area() const -> std::optional<AreaRecord>: the current generated stage's index, since_event() and a copy of the horde; std::nullopt on a load_layout stage (it cannot be regenerated). World::resume_area(AreaRecord record): rebuild stage record.stage_index exactly as load_stage does (stage, wind, a cold scent field, the player at the entry, the clock reset of the stage-local counters), then thin_horde(record.horde, params.attrition, since_event()), then take that horde in place of the spawn; a unit standing on the entry moves to the nearest free open cell in a fixed ring scan (rows then columns, nearest first), so occupancy starts valid as load_stage's does; then start_horde. Scent is not carried in the record: out of scope here
- core: if PEO-091 (save image) has landed: WRLD carries start_day, the attrition knots and the earlier-stages substep total; HORD carries each unit's fate; restore validates the curve with valid() and refuses an invalid one as Corrupt. While no save is written to disk (PEO-107 not landed) change the version 1 layouts in place; otherwise bump those sections to version 2 and read version 1 with fate redrawn as load_stage draws it. If PEO-091 has not landed, skip this unit and add a note to PEO-091 naming the fields
- test: tests/core/test_revisit.cpp, TEST_SUITE("revisit"), added to tests/CMakeLists.txt (cases under Tests)
- docs: docs/architecture.md gains a short 'Revisits (ADR-0019, PEO-094)' subsection under 'The clock' (the event clock, fate, AreaRecord, store_area / resume_area, closed-form thinning, what is not built yet: PEO-109, PEO-110) and a Revisits row in 'Boundaries that tests protect' naming the purpose case; docs/design/world-generation.md 'Revisits' gains one line pointing at peo/core/revisit.hpp

## Tests

- revisit: affected_at is 0 at the Event, non-decreasing over every day 0..3650, equals each knot at its day and the last knot's value after it
- revisit: valid() refuses knots out of day order or with falling values, and World clamps such a curve to kDefaultAttrition
- revisit: draw_fate at clock t is never below affected_at(t), and over 10,000 hashes spreads evenly over [affected_at(t), 65535] (each quarter of the range within 5% of a quarter)
- revisit: thin_horde removes exactly the units with fate < affected_at(now) and keeps the survivors in order
- revisit: one long absence equals several short ones (scenario tier): a World with start_day 7, 2,000 Dead and wind stores its area after 20 mixed actions; resuming in Worlds of the same seed at start_day 30, 90 and 365 in turn, storing straight after each resume, gives exactly the horde of resuming the first record once at day 365, and both Worlds then stay World::equivalent through 20 more actions
- revisit: resuming at the same clock loses no unit; the count lost is non-decreasing over days 8, 37, 100, 365, 1825, 3650; and from 1825 on it stays flat
- revisit: since_event keeps running across a stage exit (the player walked onto the exit) while substeps() resets
- revisit: a stored unit on the entry cell is moved to the nearest free open cell on resume, and no two of the Dead share a cell
- revisit: store_area on a load_layout stage returns nullopt
- revisit: two resumes of one record into Worlds of the same seed and clock stay World::equivalent over 20 actions (one through commit(speculate()))
- If the save unit was done: save: a resumed World saves and restores bit-identical, fates and clock included
- peo_siege --check (docs/testing.md, PEO-088): the Dead gained a field, so confirm nothing about their movement changed
- All existing core cases still pass

## Out of scope

- Player-made and player-changed things aging from last_touched (barricades, seals, stashes; ADR-0019 point 4): PEO-109, once the first player-made thing exists
- Running catch-up as a streaming job split across frames before an area enters the detailed ring, and keeping stored areas in the World or the save: PEO-110 (needs area streaming)
- Any way for the player to go back to an earlier stage: that is a gameplay change for the owner
- Generation applying the clock (areas generating thinned or looted at the current clock, ADR-0011): fate is drawn at the spawn clock instead, so no spawn count changes
- Carrying scent across an absence; the Dead leaving buildings; looting, spoilage, decay and traces
- Loading the curve from content/ (content loading is not built); the knots stay a WorldParams tunable
