# PEO-031 · verify.py cannot catch what CI catches: no release build, no clang

## Goal

A contributor who runs the documented pre-commit check cannot leave main red for a reason CI will catch.

## Context

- tools/verify.py
- CMakePresets.json
- .github/workflows/ci.yml
- AGENTS.md (run verify.py before every commit)

## Units

- tooling: add a --full mode to tools/verify.py that additionally configures and builds the headless-release preset and a clang build, mirroring the two CI jobs that the default Debug run cannot represent. Keep the default fast: --full is for before a push to main, not before every commit.
- tooling: make the clang stage skip with a clear message, not fail, when the clang runtime libraries are missing locally (this container cannot link -fsanitize with clang for want of libclang-rt-18-dev). A skipped stage must be reported as skipped, never counted as passed.
- docs: AGENTS.md and docs/roles.md currently say to run verify.py before every commit. Say instead that --full runs before a push to main. AGENTS.md is at 443/450 words, so this will need a trade rather than an insert; propose the trade in the report rather than silently cutting something.

## Acceptance

- verify.py --full reproduces both breaks that turned main red on 2026-09-29 when run against commit 69fa874, and passes against 0695dc7
- the default verify.py is no slower than it is today
- a missing clang toolchain reports the stage as skipped and does not pass silently

## Tests

- manual: run verify.py --full at 69fa874 and confirm it fails; run it at 0695dc7 and confirm it passes

## Out of scope

- changing the CI workflow itself
- adding new compilers beyond the two CI already runs
