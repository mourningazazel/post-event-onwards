# PEO-085 · Pull kernel portability and Speculation ownership: AVX2 on MSVC, no target_clones on Darwin, foreign Speculation cold-copies

## Goal

The PEO-078 pull runs its AVX2 kernel on Windows (MSVC) and on x86 Macs through a run-time check, every other target builds its plain path, and a Speculation last synced from another World always cold-copies

## Context

- src/core/src/scent_wave.cpp PEO_WAVE_KERNEL_CLONES: target_clones('avx2','default') on GCC/Clang x86 only. MSVC has no target_clones, and Apple's toolchain rejects target_clones on Darwin (ifunc), so both get the plain SSE2 path, 3-5x slower (docs/research/parallel-and-gpu.md)
- PEO-078 review: sync_from treats two waves as partners when they share a token and size; World gives each stage's wave a new token from a per-World counter, so two Worlds can hand out equal tokens and a Speculation moved between Worlds would partial-sync against the wrong field
- Every CPU in docs/design/performance-targets.md's tiers has AVX2; the M1 uses NEON through the plain path's auto-vectorisation

## Units

- core: build pull_row twice (an AVX2-targeted copy with __attribute__((target("avx2"))) on GCC/Clang, a separate translation unit compiled with /arch:AVX2 on MSVC) plus the plain copy, and pick once per process with a cpuid check (__builtin_cpu_supports on GCC/Clang, __cpuid on MSVC). Darwin x86 uses the same run-time pick without target_clones. Both copies are the same source so they give the same bits
- core: wave tokens become unique per process (a static atomic counter in ScentWave or World), so no two Worlds share one
- test: a Speculation reused across two Worlds of the same size commits exactly as step() on each (it cold-copies on the switch)
- test: a case that runs the plain kernel and the AVX2 kernel (when the CPU has it) on the same random field and compares every value

## Acceptance

- python3 tools/verify.py passes on Linux; the CI matrix (g++-13, clang++-18, release) stays green
- The Builder's Mac build passes verify (arm64 takes the plain path)
- Kernel equivalence test passes; the cross-World Speculation test passes
- On a machine with AVX2, the saturated 512x512 update is no slower than today in headless-release

## Tests

- tests/core/test_scent_wave.cpp: plain against AVX2 kernel on a random field (skips the AVX2 half only when the CPU lacks it, and says so with MESSAGE)
- tests/core/test_world.cpp: one Speculation across two Worlds
