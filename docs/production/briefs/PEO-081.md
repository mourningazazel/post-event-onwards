# PEO-081 · GPU field backend matching the CPU pull bit for bit

## Goal

A GPU backend (SDL_GPU on Vulkan, in its own library beside core) runs the calm scent update for big stages and gives the CPU pull's values, direction bytes and tile flags bit for bit, chosen by the frontend, with --no-gpu-compute always working and a lavapipe CI job proving the equality

## Context

- docs/adr/0014-threads-and-gpu-compute-in-core.md points 3-6: core holds the CPU reference behind a backend interface and creates no device; the GPU backend is a separate library the frontend selects; GPU work runs during speculation and is read back before commit; commit stays on the CPU under 1 ms
- docs/adr/0001-platforms-and-gpu-backend.md: SDL_GPU on Vulkan only, GLSL compiled to SPIR-V at build time, lavapipe on CI. docs/research/spikes/gpu-compute-probe/ (computeprobe.c, relax.comp) is the working SDL3 3.4.16 compute probe on Honeykrisp
- docs/research/parallel-and-gpu.md section 5: where the GPU pays (estimates: 1024x1024 all active about 30 us on a GTX 1080 class card and 140 us on the M1, plus a round trip of a fraction of a millisecond). At 512x512 the CPU wins, so the GPU is used only above a stage size threshold
- src/core/src/scent_wave.cpp and wave_kernels.hpp: the reference. A round is a pull from buffer A into buffer B over active tiles; integer max and subtraction only, which every GPU reproduces exactly. The GPU also has to produce what the CPU keeps beside the values: per-tile changed flags (touched/written for partner sync) and the direction bytes (PEO-079)
- Ryan, 2026-10-01 (this thread): emitters may be most of the active tiles, so the saturated field is the load to measure
- Builder machine: Asahi Linux on the M1, Vulkan through Honeykrisp

## Units

- core: peo/core/field_backend.hpp: the interface a wave's update runs through (upload the stage's masks once, run one update's rounds, hand back values, changed tiles and direction bytes). The CPU pull becomes its reference implementation; ScentWave and World use the CPU one unless given another. No SDL in core
- build: GLSL compute shaders under src/gpu/shaders compiled to SPIR-V at build time (glslc or glslangValidator, found or fetched as SDL is), embedded in the peo_gpu library; the build works with PEO_BUILD_FRONTEND off and skips peo_gpu when no shader compiler is found, saying so
- gpu: peo_gpu library (links SDL3 and core): device from the frontend, buffers sized once per stage, one dispatch per round over all tiles (no active list yet), changed flags per tile and direction bytes in the same pass or a second one, readback of values, flags and bytes. No allocation per update once warm
- app: create the GPU device when available; use the GPU backend for stages at or above a named size threshold (default from your measurement where the GPU beats 4 CPU workers), CPU below it; --no-gpu-compute forces the CPU. The speculation worker dispatches and reads back; commit never waits on the GPU
- test: a GPU equivalence test (in a separate test binary that links peo_gpu, skipped with a MESSAGE when no Vulkan device exists): random walled stages, emitters on most tiles, a walker, 120 updates, values, tile flags and bytes compared with the CPU reference after every update; plus World goldens with the GPU backend
- ci: a job installing Mesa lavapipe that builds peo_gpu and runs the GPU tests on it
- docs: architecture.md (peo_gpu beside core, the backend seam); research section 5 marks what is built with the measured numbers

## Acceptance

- verify passes; the lavapipe CI job is green and its log shows the GPU tests ran, not skipped
- GPU and CPU give bit-identical values, tile flags and direction bytes on every update of the equivalence test, and identical worlds in the GPU World goldens
- --no-gpu-compute, and a machine with no Vulkan device, run exactly as today
- M1 (Honeykrisp), headless-release, calm field with emitters on most tiles: report the GPU update including readback against the CPU at 1 and 4 workers, at 512x512, 1024x1024 and 2048x2048; the GPU path must beat 4 CPU workers at 2048x2048, and the threshold is set where it starts to
- Commit stays under 1 ms with the GPU backend in use

## Out of scope
