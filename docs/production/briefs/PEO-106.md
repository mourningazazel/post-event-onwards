# PEO-106 · Warn before WORK_QUEUE.json hits its word cap

## Goal

tools/work_queue.py owns the WORK_QUEUE.json word cap: it warns once the queue is within a fixed headroom of the 2500-word cap, refuses (writing nothing) a note that would push it over, and tells the Builder where the report goes instead, so a report is never lost at verify time as PEO-099's was at c682498. Also fix the stale '200 mixed actions' comment in tests/core/test_world.cpp (the case now runs kActions = 80).

## Units

- tools: in work_queue.py add QUEUE_WORD_CAP = 2500 and QUEUE_WORD_HEADROOM = 300 (comment: largest report seen was 172 words), content_words(node) -> int (the string-value word count words_in_json does today: dict values, list items, str.split, keys and numbers not counted) and word_budget_warning(words) -> str | None: None below cap - headroom; at or above it 'queue warning: WORK_QUEUE.json has N of 2500 content words (M left); complete reviewed items before the next report'; over the cap 'queue warning: WORK_QUEUE.json has N content words, over its 2500 cap; verify will fail'
- tools: cmd_note and cmd_set --note compute content_words of the queue with the note added; over QUEUE_WORD_CAP they print the over-cap warning plus 'note refused, nothing written: rerun without the note (set --status still works) and put the text in the commit message, naming the commit in a one-line note once there is room' to stderr and return 1 without saving. Otherwise save, then print any word_budget_warning to stderr (stdout stays the status line). cmd_add warns the same way after saving
- tools: cmd_summary prints the warning line when there is one; cmd_check prints it as a non-failing 'queue note:' line (verify then shows it every run)
- tools: validate_docs.py uses work_queue: words_in_json returns work_queue.content_words of the parsed file and WORD_CAPS['WORK_QUEUE.json'] is work_queue.QUEUE_WORD_CAP (keep the D-009 comment)
- test: validate_docs.py gains queue_budget_self_test(), run by --self-test (print 'queue budget self-test ok' alongside 'license self-test ok', non-zero exit if either fails) and by the normal run like license_self_test.
