# PEO-091 · Save file: scoped sections, two fallbacks (ADR-0017)

## Goal

peo::core writes a World to a versioned, sectioned, checksummed save image in memory and reads it back into a World that continues bit-identical to the one never saved; every section declares its ADR-0017 sync scope, and a corrupt, truncated or newer-format image is refused with a status naming why, never a crash. File rotation, the crash flag and the in-game offer of the previous copy are PEO-107; zstd is PEO-108.

## Units

- core: peo/core/save.hpp + src/core/src/save.cpp, the container, knowing nothing of World. enum class SyncScope : std::uint8_t { World = 1, Character = 2, Local = 3 }; struct SaveSection { std::uint32_t id (four ASCII chars, little-endian); std::uint16_t version; SyncScope scope; std::vector<std::byte> payload; }; struct SaveImage { std::uint32_t format; std::string build; std::vector<SaveSection> sections; }; inline constexpr std::uint32_t kSaveFormat = 1; std::uint32_t crc32(std::span<const std::byte>) (IEEE, reflected 0xEDB88320, constexpr table); std::vector<std::byte> write_save(const SaveImage&); and read_save(std::span<const std::byte>) -> SaveRead { SaveStatus status; SaveImage image; std::vector<SaveIssue> issues; } with enum class SaveStatus { Ok, BadHeader, Truncated, NewerFormat, Corrupt } and SaveIssue { std::uint32_t section_id; SyncScope scope; std::string what; }
- core: the byte layout, all little-endian, written byte by byte (never memcpy a struct): magic 'PEOSAVE' plus a 0 byte, u32 format, u16-length build string, u32 section count, then per section u32 id, u16 version, u8 scope, u8 codec (0 = raw; PEO-108 adds 1 = zstd), u64 payload length, u32 crc32 of the stored payload, payload. A crc mismatch or unknown codec in a World or Character section makes the image Corrupt; in a Local section the section is dropped with an issue and the status stays Ok; an unknown section id is skipped with an issue. Lengths are checked against the bytes left before any allocation, so a hostile length is Truncated, not a huge vector
- core: a little ByteWriter / ByteReader pair for payloads (u8..u64, i32, Vec2i, length-prefixed vectors) in peo/core/byte_io.hpp; the reader keeps a failed flag instead of throwing and returns zeros once failed
- core: Rng gains state() and a way to rebuild from those four words; ScentWave gains a restore entry point taking its values and update count that leaves the derived buffers (masks, flow, active and stale tiles, carry, partner token) as a cold start of the same stage rebuilds them. If a derived buffer cannot be rebuilt bit-exactly, save it instead; the continuation test decides
- core: World::save(std::string_view build) const -> SaveImage, and World::restore(const SaveImage&, std::vector<SaveIssue>& issues) -> SaveStatus, which builds a new World and move-assigns it only on Ok, so a refused image leaves *this untouched (executor and field backend pointers are kept, never saved). Sections, one per system, each with its own version 1: 'WRLD' (World: seed, every WorldParams field, stage index, whether the stage is generated or hand-built, turn, substeps, updates, Rng state), 'STAG' (World, hand-built stages only: size, blocked, openness, entry; a generated stage is regenerated from seed and index), 'SCNT' (World: scent values and update count), 'HORD' (World: the horde and whatever HordeState and the desire field hold between turns that cannot be rebuilt), 'OCCL' (World: the occupancy log), 'CHAR' (Character: the player's position; written as character 0 of a count so a second character is a second record, nothing assumes one player). No Local section yet: the app adds those later
- core: restore validates every value against the stage it built: grid sizes match, the player and each of the Dead stand on open in-bounds cells, slot indices and pending moves are in range, the clock is consistent with update_period. Any failure is Corrupt with an issue naming the section and the field
- test: tests/core/test_save.cpp, TEST_SUITE("save"), added to tests/CMakeLists.txt (cases under Tests)

## Acceptance

- ctest --preset headless passes, including every case listed under Tests; the unit tier stays under its D-033 budget
- A World saved after mixed actions and restored is World::equivalent to the original, and stepping both through the same further actions keeps them equivalent after every action, on a generated stage with wind and on a load_layout stage
- Saving the same World twice gives identical bytes, and saving the restored World gives the same bytes as the original
- Every section in a saved image declares a scope; WRLD, STAG, SCNT, HORD and OCCL are World and CHAR is Character
- A flipped payload byte, a cut-off image, a bad magic and a format above kSaveFormat each return their status (Corrupt naming the section, Truncated, BadHeader, NewerFormat) and leave the World unchanged; none crash under the ASan/UBSan job of verify.py --full
- src/core still includes no file, stream or SDL header (save images are bytes in memory; the app owns files from PEO-107)
- python3 tools/verify.py --full passes

## Tests

- save: crc32 of '123456789' is 0xCBF43926
- save: an image of three sections, one per scope, reads back field for field
- save: a flipped payload byte in a World section makes the image Corrupt and names that section
- save: a corrupt Local section is dropped with an issue and the image is still Ok
- save: a truncated image, a bad magic, a newer format and a section length past the end each return their status
- save: an unknown section id is skipped with an issue
- save: World::save is deterministic and restore(save) saves the same bytes
- save: a restored world continues bit-identical to the one never saved (scenario tier: generated stage with wind_max > 0 and 200+ Dead, and a load_layout stage; at least 40 mixed step / wait / run actions before the save and 40 after, World::equivalent after each; one run uses commit(speculate()) after the restore)
- save: an image whose player stands on a wall is Corrupt and leaves the World unchanged
- All existing core cases still pass

## Out of scope

- Writing files, swapping copies, the two fallbacks, the crash flag and offering the previous copy in game: PEO-107
- zstd compression: PEO-108 (codec byte 0 only here)
- Content ID remap, generic stand-ins and junk: PEO-092, deferred
- Local-scope sections (settings, key bindings, UI layout): when the app has them
- Stable 64-bit entity IDs (ADR-0002): the horde's index is its identity until the ECS lands
- Saving a Speculation: it is recomputed after restore
- Any change to scent, the Dead or the desire field's behaviour
