> resemble current ones, but are believable brand names. Later on, as you create these items, you
> will create a handful of brand options for each item that it would make sense to have one for,
> as a property tag, and using realistic brand association so a brand of cereal might be of the
> same parent brand as bread. This should be a relationship, so perhaps certain tags are flagged

## What this settles

- **Name: "Post Event: Onwards".**
- **D-CM1: physically plausible attachment.** The *attached* item carries an **attachment
  surface** and an **attachment strength**, relative to its size and weight.
- **D-CM2: joints cost something,** and each method has its own properties (e.g. glue cures;
  rope suits large, not small objects). The system must be deep, but easy to understand at its
  base.
- **D-CM3: generated descriptions.** Surface details come from properties and combinations of
  properties, written as prose rather than tag lists.
- **D-CM4: no real brands.** Invented, believable brands with parent-company relationships. Items
  get brand options, and name-altering tags put the brand into item names.
