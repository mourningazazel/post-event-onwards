# N008 — AI-authored content: archetypes, properties, tags, and environment-driven detail

- Date: 2026-09-27
- Source: owner, in session

> So as another note for design. We will be wanting to build out generation in the world, using
> your AI powers. To do this, we need to structure what will be generated by AI, to account for
> individual traits the items or objects will have, and only include the level of detail on items
> that really has to do with those traits, or details that lend to better world building or
> environmental description. For example, if we were to create a complete enemy unit, down to every
> detail, we would need to include all the things that went into making that unit. I want this
> world to be highly sandboxed, so there will be detail where not entirely necessary. For this unit
> we would have a generalized garmet of clothing for top and bottom, shoes, maybe gloves, hats, etc.
> Accounting for items like coats, or socks. Those should be environmentally focused, as the mobs
> are not individuals to themselves as much as outputs of their environments. An office worker
> wearing a suit, etc. This is why i wanted to approach items and objects in a way that allows for
> limitless depth on relationships, so we can build out chains of relationships on these units and
> the objects and containers in a building etc. and then in the buildings and overworld, as well as
> the items and items within containers etc, build out lists of what items you would actually see
> in real life, and in similar quantities, but only including items you feel woudl have an actual
> in-game use, or serves as sufficient flavor for the environment or serves an aesthetic or
> pleasing purpose for the player character. You should focus on creating more archetypal items,
> and then using the way we structure objects to add further details onto them. You can then
> reference details for other calculations in a sort of tagging system, or by giving it additional
> properties, that would allow other objects or functions to use it generically. Since you will be
> filling in the values for all these items, you can come up with unique and in depth tagging and
> property systems for these items, and update them when needed even, to let objects be used
> together or used in crafting, in ways that just make sense logically, but don't need to be
> pre-programmed. If you're able to attach an object to the end of an object with "handle" /
> "handled" (implying it has a handle you can wield it by), you shoudl be able to attach any object
> of applicable size (given by the item, with "handle" requiring a "maxAttachSize" or similar
> property) and have it behave. On the object attached, it would make sense then to have a property
> such as "ifImpacted" for a generic "what happens if this gets hit hard" property, that could be
> pretty generic like "breaks easily" for " wouldnt sustain an impact" or "causes blunt force"
> which would use a calculation on weight and hardness, or "cuts " etc etc.. You should put some
> thought to what would be useful for properties and tags in a game like this.
